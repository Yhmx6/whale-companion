# 引导生成路线的缺陷清单

> 2026-10-27。适用对象：`route="guided"`（项目主路线）。
> 全部数字来自实测，不是估计。对应实验脚本写在每条后面。
> 按**用户能不能忍**排序，不按"技术上难不难修"排序。

---

## 先看这个：躺姿的尺寸 bug（2026-10-27 已修复）

**症状**：用户报"这张用了精准尺寸，但尺寸太小了，不符合 60cm"。
一张沙发照里她只有指甲盖大（画面高 10.6%）。

**根因不是"精准尺寸"不准，是公式的隐含假设被违反了。**

`target_h = person_h_px × scale` 读作"人物 175cm 时她 60cm"，
但它隐含假设**人站着、框高就是身高**。躺着的时候，人物框的高度
只是身体**厚度**，身高跑到了横向。

实测那张图（1400×933，人侧躺）：

| 量 | 数值 |
|---|---|
| 人物框 | `[203, 340, 816, 647]` |
| 框高 | **287px**（身体厚度） |
| 框宽 | **859px**（躺着的长度） |
| 按框高算 | 287 × 0.343 = 99px = 画面高 **10.6%** |
| 按身体长度算 | 859 × 0.343 = 296px = 画面高 **31.7%** |

**差 3 倍**。而且误差方向是"偏小"，用户一眼就看出来不对。

**修法**：新增 `PhotoProfile.body_len_px(w, h)`——取框的**长边**，
但只在明显横躺时（`宽 > 高 × 1.2`）才用宽度。

留 1.2 的余量是因为坐着的人框宽可能接近框高（盘腿坐、抱膝坐都是
近似方形的团），那种情况身高仍然是纵向的。

回归验证：10 张带人物素材 + 3 张真实照片里，**只有沙发侧躺那张改用宽度，
其余 12 张全部不变**——判据没有误伤站姿和坐姿。

`body_len_px` 替换了四处调用：立绘路线的目标高度、引导生成的目标高度、
规划器看的尺度提示、solo 老路径的重定位。

---

## 一句话结论

**这条路线把"她能自然地出现在照片里"做到了，但把"她有多大、下次还能不能
一样、要花多少钱"这三件事丢了。** 前两件是硬缺陷，第三件是产品决策。

具体地：位置/动作/表情/遮挡/避障这五项都能用；尺寸、可复现性、成本三项不行。

## P0 — 影响"这张图能不能用"

### 1. 尺寸做不到 60cm，系统性偏大 1.13~1.78 倍

**现象**：视觉上她像一个 90~110cm 的小孩，不是 60cm 的玩偶。坐在长椅上
能占满半个座面，站在人旁边头顶到大腿而不是膝盖。

**数据**（10+ 张，`s3/measure.py` 逐像素客观测量）：

| 场景 | 60cm 应占画面高 | 实测 | 倍率 |
|---|---|---|---|
| 长椅·坐着的人 | 31.1% | 35.2% | 1.13× |
| 街道·走路的人 | 18.7% | 30.7% | 1.64× |
| 咖啡桌 | 25.2% | 41.1% | 1.63× |
| 扶手椅 | 26.4% | 44.8% | 1.70× |

**根因**：模型对"卡通小人"有一个内在的尺寸先验，约 **26~30% 画面高**是它的下限。
目标小于这个就必然被顶上去了。四条控制手段全部实测无效：

| 手段 | 结果 |
|---|---|
| 提示词把"框"定义成"从呆毛尖到鞋底、尾巴末端到头发外侧" | 1.51× → 1.49× |
| 提示词加实物参照（"头顶刚过人物膝盖"） | 无效 |
| 引导图里把她**缩小一半**（21.3%→10.6%） | 完全无视，成品稳定 31~34% |
| 换成**纯色剪影**要求"填满形状" | 32.8%（贴立绘时 31.8%） |

反向验证过：引导图放大到 42.8%，成品跟到 64.1%（3.0×）。
所以它是**只在大尺寸时按比例跟**，小尺寸就按自己的先验重画。

**现在怎么处理**：`GUIDED_SIZE_FLOOR = 0.30` 提前告警，每次返回
`measured_pct` / `size_err`。**不假装解决了。**

**能不能修**：这条路线内修不了。要精确 60cm 只能走 `route="sprite"`。
唯一的现实出路是换模型或等模型更新。

`step20_size_measure.py` / `step21_size_bias_calib.py`

---

### 2. 可复现性差：同一张图跑三次可能给三个结果

**现象**：同一张照片重试，她的位置、动作、表情都可能变。

**数据**：

- 同一张 c09 吧台图，四轮解析给出的物品数：**4 / 4 / 0 / 4**
- 同一张 p05，连问三次给出三个动作：`seat_edge_sit` / `leg_hands_behind` / `leg_hug_knee`
- 表情同样抖（10 张里"温柔"的占数在三轮测试中分别是 5 / 3 / 2）

`temperature` 已经设成 0，**并没有让它稳定**。

**根因**：整条链路有两处 VLM 生成（照片解析 + 场景规划），都不可复现。
上游抖一点，下游位置就跟着偏。

**后果**：用户重试得不到可预期的结果；A/B 实验必须冻结 VLM 才有意义；
"调好了一张"不代表"每张都好"。

**现在怎么处理**：`objects` 为空时重试一次（能救大部分，治不了根）。

**能不能修**：能，但要投入——两次独立解析取交集、或者按区域扫描。
成本会翻倍。

`step27_mood_pick.py`（看单次波动）/ `step24_batch3.py`（看批量波动）

---

### 3. 成本从 0 变成 0.12 元 / 张，耗时从 3 秒变成 16~22 秒

**现象**：不能免费试错，不能一次出十张让用户挑。

**数据**：单张 0.12 元（flash）/ 16~22 秒。立绘路线是 0 元 / 3~5 秒。

**后果**：产品形态受限——"多候选挑一张"这种交互在成本上不成立
（4 张 = 0.48 元 / 一分钟以上）。

**能不能修**：这是渲染本身的成本，只能靠产品设计绕（比如先给 1 张预览，
用户满意再要变体）。或者把不敏感的场景切回 sprite。

## P1 — 影响"像不像"

### 4. 接触阴影要模型自己画，经常很淡甚至没有

**现象**：她像"浮"在座面上，没有压下去的重量感。

**数据**：E04 扶手椅那张几乎没有接触阴影；其它场景有但不稳定。

**对比**：立绘路线是**程序化**画阴影（`s3ops.render_shadow_matte` +
`shadow_under` 保证阴影在她下面），强度可控、每次都一样。

**能不能修**：靠提示词要求"画出接触阴影"效果有限。真要稳，得在生成后
用程序补一层——但那时她已经和环境融合了，没有干净的 alpha，补起来会脏。

---

### 5. 没有重打光，暗光/逆光场景容易脱节

**现象**：她在暖光场景里偏冷，逆光场景里脸上没有轮廓光。

**对比**：立绘路线有 `match_ambient` + 沿光向的明暗梯度 + 色温从照片量。

**现状**：引导生成靠模型自己融合，效果时好时坏。P04 咖啡桌那张她的受光
和桌面一致，P07 窗台那张脸偏亮但没窗光的方向。

---

### 6. 表情画得准不准，因表情而异

**现象**：`shy`（害羞）非常准——脸红、低头、手绞在一起；
`smug`（得意）**被画成"俏皮眨眼"**，没画出"一边嘴角翘、下巴抬起"。

**数据**：强制指定四种表情逐张验证，三种准一种偏。

**根因**：强表情（害羞、惊讶、好奇）有明确的五官动作可画；
微表情（得意、温柔）依赖细微的不对称和程度，模型抓不住。

---

### 7. 避让只挪横向，不检查"支撑面还在不在她身下"

**现象**：c07 窗台那张，为了躲绿植横向挪了 582px，结果她被推到窗台最左端，
多半个身子悬在窗台外面。

**根因**：避让只在 x 轴上找空位，没有回头验证"新的落点下面还有没有东西撑着"。

**能不能修**：能，加一步校验——挪完再看落点是否还在目标物体的 x 范围内。

## P2 — 已知边界

### 8. 2.5D 场景是矩形占位，不是真实轮廓

一只杯子会占掉它整个外接框。偏保守（宁可多避一点），但会出现
"旁边明明有空隙却不敢放"的情况。

同深度的两件东西分不出先后（桌上并排两个杯子），按面积近似。

### 9. 不支持 mask 局部重绘

最彻底的做法是给 mask 只重绘她那一块，尺寸和位置就由 mask 定死了。
这支 API 传 `mask` 返回 200 但**静默忽略**（两个矩形只框左边，结果两个都被换成猫）。

所以尺寸问题没有"技术上更彻底"的解法，只能等模型支持。

### 10. 一次只出一张，没有候选

`run_guided` 内部没有"生成 N 张挑一张"的逻辑。要加的话成本线性增长。

### 11. 任务状态只在内存里，刷新就丢

前端已经接了（一键出图默认走这条路线，高级选项里能改路线/表情/动作）。
但任务表 `JOBS` 是进程内字典：**页面一刷新、服务一重启，进行中的任务就查不到了**，
产物文件还在 `output/runs/` 下，只能靠 job id 找回。要做成产品得落到磁盘或 Redis。

### 12. 没有金标准集

所有阈值（尺寸下限 0.30、避让容差 0.15、表情收窄的 0.12/0.35/0.65）
都是在 10~20 张图上定的。换一批素材可能要重标。

## 什么时候该切回 `route="sprite"`

| 情形 | 为什么 |
|---|---|
| 需要精确 60cm | sprite 是程序 resize，100% 精确 |
| 要批量出图（>10 张） | 0 元 vs 0.12 元/张，差一个数量级 |
| 调几何 / 阴影 / 抠图问题 | 那些问题用 0 元路线复现快得多，和生成模型无关 |
| 用户明确要"不要被挡住" | sprite 永远贴在最前，没有遮挡问题 |
| 服务要抗并发 | 0 秒 vs 16~22 秒 |

反过来，只有这几种情况值得花 0.12 元：**要被人物挡住 / 要表情 / 要躲开桌上的东西**。
