# 11 · 场景路由与锚点体系（v0.1）

> 回应的问题：
> 1. 目前小鲸鱼的大小、动作、位置是怎么定的？
> 2. 如果预建一套按照片场景（全身/半身/自拍/长椅/道路/桌面/沙发/床）划分的动作库，
>    把动作和位置与人物、物件强关联；先检测人物、再检测可交互物件、都没有就拒绝，
>    会不会更好？

---

## 一、现状：三层逻辑，只有一层半是程序控制的

### 1.1 大小

```
person_h  = VLM 给出的「整个人」框高（像素）        ← 唯一尺子
target_h  = person_h × action.scale_ratio            ← 动作自带系数
target_w  = target_h × 0.78                          ← Q 版宽高比
```

`scale_ratio` 语义是**占人物身高的比例**，当前标定：

| 动作 | scale_ratio | 折算 |
|---|---|---|
| `leg_hands_behind`（站） | 0.28 | ≈46cm |
| `leg_hug_knee`（坐） | 0.26 | 坐姿视觉高度天然更矮 |
| `foot_sit` | 0.19 | 坐鞋面，最小 |
| `pull_trouser`（蹲） | 0.24 | |

缩放靠 `rescale_to_height()`：掩码把她摘出来 → 按目标高度重采样 → 底边钉在算出的
脚底线 → 贴到干净的原照片上。**这一步与提示词无关，模型说什么都不影响结果。**

### 1.2 位置

```
leg_cx   = 腿框中心 x
leg_w    = 腿框宽
center_x = leg_cx - (leg_w/2 + target_w/2 + 6)   ← 永远放腿的左侧
bottom_y = 腿框底边 = 鞋底 = 地面线
```

`px`、`py` 最后夹紧在 `[2, W-nw-2]` / `[2, H-nh-2]` 内，防止贴边被裁。

**同样是纯程序计算。** 提示词里那条 `Image 1 x1 y1 x2 y2` 的位置约束仍然在发，
但它现在只影响"模型画在哪"，而画在哪已经不重要了——反正会被搬走。

### 1.3 动作

- 默认开放 5 个：`shoulder` / `peek` / `leg_hands_behind` / `leg_hug_knee` / `hem_peek`
- 自动匹配走 `vlm_match_action()`：把 5 个动作的 id、名字、desc、`needs`、`framing`
  拼成清单喂给 VLM，让它挑一个，返回 `{action_id, confidence, reason, visible_parts}`
- **没有任何硬性过滤**。`framing` 字段（`closeup/half/full`）声明了但代码里从未使用，
  只透传给前端展示；`needs` 也只是喂给 VLM 的文字

### 1.4 ⚠️ 最关键的一条：程序化控制只覆盖 ground 类动作

`app/pipeline.py:269`：

```python
if a0 and a0.support == "ground":     # 只有这一类才做尺度归一 + 重定位
```

5 个默认动作里：

| 动作 | support | 尺度归一 | 重定位 | 阴影 |
|---|---|---|---|---|
| `leg_hands_behind` | ground | ✅ | ✅ | ✅ |
| `leg_hug_knee` | ground | ✅ | ✅ | ✅ |
| `shoulder` | person | ❌ | ❌ | 交给模型 |
| `peek` | person | ❌ | ❌ | 交给模型 |
| `hem_peek` | person | ❌ | ❌ | 交给模型 |

**也就是说：三个上半身动作的大小和位置，至今仍然完全由模型决定**，
和修复前的贴腿动作一样不可控。这是现状里最大的不对称，也是本次讨论的起点。

### 1.5 场景概念：实际上不存在

`surface` 参数只有 `ground / chair / bed / desk / wall` 五个值，但在贴贴模式下：

- `SURFACE_SPEC[surface]["contact_ratio"]` **没有生效**——贴贴路径的阴影接触点
  一律取 `bb[3]`（包围盒底边），不管她是坐椅子还是站地上（`pipeline.py:349`）
- `surface` 唯一的实际作用是选阴影预设（`sun_left` vs `left`）
- `anchor_for(surface)` 只被 **solo 模式**（用户手画框）使用

所以"场景"这一维在贴贴模式里是空的。

## 二、你的方案：方向对，但有三处必须修正

### 结论：**对，而且这是唯一能继续往下走的路。** 但要按下面的方式落，否则会踩回已经证伪的坑。

### ✅ 对的部分

1. **场景路由（人物优先 → 物件兜底 → 拒绝）**。现在是"只有人物一条路"：照片里
   没人物，整套动作库直接失效。这张照片本来能用，却被浪费了。
2. **动作与物件几何强绑定**。这解决了当前最大的遗留问题——接触点靠猜。
   "坐椅面"意味着接触面在椅面上方约 86% 处，这个数是可以从椅框算出来的，
   而不是像现在这样一律取包围盒底边。
3. **拒绝路径**。生成一张废图要花 0.12~0.30 元和 15~70 秒，还要用户自己判断好坏。
   提前说"这张照片不合适"更诚实。

### ⚠️ 修正一：位置不能回到动作库的文案里

你说"把小鲸鱼的动作和位置与人物和物件强关联"。如果这个"位置"是指**写进动作描述**，
那就是我们已经证伪两次的路：模型对"放在腿边""约40厘米"这类软约束的遵从度很低，
实测偏大 1.5~2 倍、位置漂到鞋面上。

**正确形态**：动作库存的是**几何契约**，不是文案。

```
动作不写"坐在长椅左端"，而是写：
    anchor_kind = seat_plane
    anchor_part = bench_seat
    place       = on_top
    ruler       = anchor_width      # 用椅面宽当尺子，不是人物身高
    scale_ratio = 0.30
```

位置由程序从锚点框算出来，文案只负责"画成什么样"。

### ⚠️ 修正二：尺子必须跟着路由换

现在是 `person_h × scale_ratio`。走物件路线时这个公式会崩：

- 长椅在画面里可能只占 300px 宽，人物占 900px 高——用人物身高当尺子，
  她会和长椅完全不成比例
- "她坐在椅面上"真正要保证的是**她的坐高 ≤ 椅面高**，这是一个物件约束

所以 `Action` 要新增 `ruler` 字段：

| ruler | 用什么当尺 | 适用 |
|---|---|---|
| `person_height` | 人物框高 | 人物身上的动作（肩/腿/衣摆） |
| `anchor_height` | 锚点框高 | 树干、电线杆（她的高度 ≈ 锚点高的某个比例） |
| `anchor_width` | 锚点框宽 | 长椅、沙发、床沿、桌沿（坐上去要按宽度定） |
| `ground_span` | 脚底线到画面底的距离 | 纯地面动作 |

### ⚠️ 修正三：动作库不要按场景枚举，要按**锚点原型**枚举

8 个场景 × 每场景 5 个动作 = 40 个动作，每个都要单独实测 tier——
这个规模维持不住，而且场景之间大量动作是重复的（"坐在长椅上"和"坐在沙发上"
在几何上是同一件事：一个水平面 + 一个靠背）。

**收敛成 5 个锚点原型**：

| 原型 | 几何 | 典型载体 | 动作举例 |
|---|---|---|---|
| `person_part` | 人物身上的部位 | 肩、头、衣摆、小腿、手 | 坐肩、探头、扒衣摆、抱小腿 |
| `seat_plane` | 水平坐面（可带靠背） | 长椅、沙发、床沿、桌沿、台阶 | 坐边缘、盘腿坐、趴靠背 |
| `vertical_prop` | 竖直柱状物 | 树干、电线杆、路灯、栏杆 | 抱柱、绕柱探头、靠柱站 |
| `horizontal_edge` | 细长水平边 | 栏杆横杆、桌沿、窗台、栏杆 | 坐边、趴边、悬挂 |
| `ground_plane` | 开阔地面 | 道路、草地、地板 | 坐地抱膝、站腿边、蹲 |

**场景只是"能提供哪些锚点原型"的映射表**，不是动作库的组织维度：

```
道路   → ground_plane (+ person_part)
长椅   → seat_plane, horizontal_edge (+ person_part)
沙发   → seat_plane, person_part
床     → seat_plane, person_part
桌面   → seat_plane, horizontal_edge
树干   → vertical_prop
全身照 → person_part(legs/feet), ground_plane
半身照 → person_part(hem/shoulder/torso)
自拍照 → person_part(shoulder/head/hem)
```

这样动作库只随**原型**增长（5 条线），场景只是查表。

## 三、收敛后的架构

### 3.1 数据结构

```python
@dataclass
class Anchor:
    kind: str            # person_part | seat_plane | vertical_prop | horizontal_edge | ground_plane
    part: str            # shoulder / hem / legs / feet / seat / backrest / trunk / rail / ground
    bbox: list[int]      # 0-999 归一化 [x1,y1,x2,y2]
    occluded: bool = False
    usable: bool = True  # 尺寸/清晰度门槛判定结果
    why_not: str = ""    # usable=False 时写原因，用于给用户解释

@dataclass
class PhotoProfile:
    framing: str             # closeup | half | full | selfie
    person: list[int] | None
    light: str               # left | right | top | flat
    scene: str               # indoor | outdoor | unknown
    anchors: list[Anchor]
    verdict: str             # usable | weak | reject
    reason: str
```

`Action` 新增四个字段：

```python
anchor_kind: str = "person_part"
anchor_part: str = ""
ruler: str = "person_height"
place: str = "left_of"        # left_of | right_of | on_top | in_front | behind | center
requires_ground_plane: bool = False
```

### 3.2 路由决策树

```
PhotoProfile（1 次 VLM 调用，约 1.5 秒）
│
├─ person 存在？
│   ├─ 是 → framing 校验
│   │        ├─ full   → 候选 += person_part(legs/feet) + ground_plane
│   │        ├─ half   → 候选 += person_part(hem/torso/shoulder)
│   │        ├─ closeup→ 候选 += person_part(shoulder/head)
│   │        └─ selfie → 候选 += person_part(shoulder/head/hem)
│   │
│   └─ 否 → 跳过人物分支；若同时没有可用物件 → reject
│
├─ 物件锚点筛选（无论有没有人物都要做，人+物双锚定的效果最好）
│   └─ 每个 anchor 过三道门槛：
│        ① 尺寸下限：框高/宽 ≥ 画面短边 × 8%（太小的椅子坐上去像假的）
│        ② 遮挡：occluded → 降权，不直接排除
│        ③ 可达性：与人物框距离 ≤ 人物身高 × 1.2（否则在画面另一头，构图断裂）
│
├─ 候选动作 = {a | a.anchor_kind 命中某个 usable anchor}
│
├─ 排序：tier(A>B>C) → 锚点可靠度 → 置信度
│     锚点可靠度：person_part > horizontal_edge > seat_plane > vertical_prop > ground_plane
│     （这是实测出来的：长边比小区域好定位，「抓自己」比「抓别人」简单一个数量级）
│
└─ 候选为空？
    ├─ 有 person 但 framing 只支持 closeup → verdict=weak，退到最保守动作（hem_peek / shoulder）
    └─ 连人物都没有                  → verdict=reject
                                        "这张照片里没找到人物，也没有可依附的物体，
                                         建议换一张能看清人或椅子的照片"
```

### 3.3 成本账：**不增反减**

现在每次生成要调 2 次 VLM：
1. `build_companion_prompt` 里的 `vlm_locate()` —— 拿腿部框写位置约束
2. 后处理里的 `vlm_locate_pair()` —— 拿 person 框当尺子 + light

改成 `PhotoProfile` 之后合并成 **1 次**：一次要回 framing + person + anchors + light。
「自动匹配」按钮的 `vlm_match_action()` 也可以在同一个 profile 上本地跑（不需要再调 VLM）。

**净效果：2 次 → 1 次，还多拿到 framing 和物件锚点。**

## 四、风险与门槛

### 4.1 VLM 一次问太多会掉准

现在 `vlm_locate_pair` 一次要 2 个框 + 1 个光向，实测很准（person/legs 误差 <2%）。
但再加上"找出画面里所有可交互物件并分类"，是**多目标检测**，难度高一个量级，
`doubao-seed-2-1-lite` 很可能给出漏检或错框。

**对策**：分两级
- 第一级（必做）：framing + person + light + `has_object_hint`（是/否，只做有无判断）
- 第二级（仅当 `has_object_hint=true`）：单独问"画面里有哪些可坐/可依靠的物体，
  给出框"。这一步失败了只损失物件分支，不影响人物分支

不要一次问 8 个问题。宁可两次便宜调用，也不要一次错答案。

### 4.2 拒绝率可能高得不能接受

硬拒绝的代价是用户挫败。日常随手拍里，桌面特写、宠物照、纯风景照都会被拒。

**对策**：三级
- `strong`：锚点清晰，直接生成
- `weak`：锚点勉强可用，仍然生成，但在结果上标注"这张照片的依附关系可能不太自然"
- `reject`：连弱锚点都没有，才拒绝

而且 reject 时给**可操作建议**（"离人物远一点再拍一张"），而不是干巴巴说不可用。

### 4.3 动作库的实测成本

每新增一个动作要跑真实生成（0.12~0.30 元 + 15~70 秒）才能定 tier。
40 个动作 = 至少 40 次实测 ≈ 5~12 元。收敛到 5 个原型后，
新增一个原型只需实测 3~5 个代表动作。**这是按原型枚举的最大好处——省的是实测成本，不只是代码量。**

### 4.4 一个反直觉的提醒

`seat_plane` 类动作（坐长椅/沙发/床）看起来比贴腿简单，但**不一定**：

- 现在是"她贴在人身上"，遮挡关系由人物身体决定，模型有大量先验
- 改成"她坐在长椅上"，需要处理"椅面透视"——椅面是斜的，她的坐姿要和透视对齐
- 而且她必须被椅子的**扶手/靠背**部分遮挡才自然，这又回到遮挡关系

**建议 `seat_plane` 先只做"坐前边缘、双腿垂在椅外"这一种姿态**——
它不需要处理扶手遮挡，几何最简单。

## 五、落地顺序（建议）

| 步骤 | 内容 | 收益 | 风险 |
|---|---|---|---|
| **P0** | 把 `PhotoProfile` 合成一次 VLM 调用，产出 framing + person + light + anchors；路由先用"framing 硬过滤"（全身照不给半身动作） | 立刻修掉"半身照匹配到腿部动作"这类错配；VLM 调用 2→1 | 低。不改生成链路 |
| **P1** | `Action` 补齐 `anchor_kind / anchor_part / ruler / place`，把位置计算从硬编码的"腿左侧"泛化成按 `place` 算 | 位置逻辑可复用，为物件路线铺路 | 中。要回归 5 个现有动作 |
| **P2** | 加 `seat_plane` 原型 + 长椅/沙发/桌面三个动作（先只做"坐前边缘垂腿"） | 打开"无人物照片"这一大类 | 中高。透视与遮挡要实测 |
| **P3** | 加 `vertical_prop`（树干/电线杆）+ 拒绝路径与三级 verdict | 覆盖户外场景 | 中 |

**不要一次做完 8 个场景。** P0 单独就能解决你现在最痛的问题（动作与景别错配），
而且完全不动生成链路，零回归风险。

## 六、一句话回答"会不会更好"

**会，但关键不在"按场景建库"，而在"把动作库从文案改成几何契约"。**

场景是**查表的键**，锚点原型才是动作库的组织维度；
位置必须由程序从锚点框算，不能写回提示词；
尺子必须跟着锚点换，不能一律用人物身高。

这三点做对，你的方案就是对的；任一点做错，就会退回"提示词软约束"那个已经证伪的坑。

## 七、实施记录（P0 + 上半身动作重定位）

### Step 1（P0）：PhotoProfile 合并 + framing 硬过滤 —— 已完成

**新增 `s3/profile.py`**

一次 VLM 调用同时产出：`framing` / `person` / `legs` / `light` / `selfie` / `has_prop`，
以及（按动作需要）一个 `anchor` 部位框。替换掉原来分散在两处的
`vlm_locate`（写位置约束）和 `vlm_locate_pair`（当尺子 + 光向）。

**`framing` 第一次真正参与逻辑**

`filter_by_framing()` 按景别硬过滤，实测效果：

| 照片 | 景别 | 过滤前候选 | 过滤后候选 | 选中 |
|---|---|---|---|---|
| s01_mirror | half | 5 | 3（去掉两个腿部动作） | peek |
| s02_park | half | 5 | 3 | peek |
| s03_sofa | half | 5 | 3 | peek |
| s04_full | full | 5 | 4（去掉 peek） | leg_hands_behind |
| s05_walk | full | 5 | 4 | leg_hands_behind |
| 户外全身照 | full | 5 | 4 | leg_hands_behind |

过滤后为空时退回全集——宁可给一个不完美的动作，也不要因为规则写死而拒绝
一张本来能用的照片。真正的拒绝路径等物件分支建好后再做。

**顺手修掉三个体检出来的问题**

1. **双人照框到两个人**：s02_park 有两名被摄者，`person` 框原来横跨两人，
   当尺子会把高度算成两人的并集。提示词补上"只框离镜头最近、最居中的那个"。
2. **腿框退化**：半身照里腿看不见，VLM 会返回贴着底边的横条
   （实测 s03_sofa 回了 `[0, 910, 998, 999]`）。加人体比例校验：
   腿高/身高必须落在 28%~75%，且腿框底边与人物框底边相差不超过身高的 12%。
3. **落地线取错框**：s04_full 的腿框底边是 916、人物框底边是 986，差 7% 画面高。
   改用**人物框底边**当落地线——两者定义都是"鞋底最低点"，但人物框更完整。
   沿用腿框会让她凭空浮起约 120 像素。

### Step 2：上半身动作重定位 —— 已完成，过程中推翻了一个假设

**先做错的判断**

一开始认为"上半身动作模型能画对"（肩膀、衣摆是显眼的强锚点，模型有大量先验），
所以只打算"纠大小、不动位置"，给 `rescale_to_height` 加了 `place=False`。

真跑一次 `peek` 就把这个假设打翻了：她没有被"画成扒在肩膀上"，而是被画成
**一整个小人浮在人物肩膀外侧的空气里**，位置偏到墙面上。只纠大小等于——
尺寸改对了，位置仍然是错的。

**改成和地面动作同一套：拿锚点框，搬过去**

- `Action` 新增 `anchor_edge`（`top` 坐上沿 / `bottom` 扒下沿）和
  `contact_ratio`（接触点落在她自身高度的哪个位置）
- 画像按动作 `anchor_region` 额外返回一个部位框（`ANCHOR_ASK` 里把每个部位的
  判定口径写死，避免"双肩"被理解成"框住整个人"）
- 落点：`bottom_y = 锚点边 + 8% 内压 + (1 - contact_ratio) × 目标身高`
- 水平：坐在肩膀的**外侧 22%**，不是两肩中间（中间是脖子，会盖住脸）

**`contact_ratio` 是这一轮最有价值的发现**

第一版没有它，`bbox 底边 = 肩线`，结果她的**鞋底正好压在肩线上**——
看起来是"站在肩上"，和动作名「坐肩」对不上。

接触点必须按姿态算：

| 姿态 | contact_ratio | bbox 底边相对锚点线 |
|---|---|---|
| 站立 / 坐地 | 1.0 | 对齐（脚/臀就在底边） |
| 坐在高处（肩/椅面） | 0.62 | 下沉 38% 身高，臀才落到座位上 |

加上之后，臀底落在肩线上、双腿垂在卫衣前，接触关系成立。
这个参数在 P2 做 `seat_plane`（坐长椅/沙发）时会直接复用。

**被搬动后必须补接触阴影**

模型原来在她身上画的接触暗部留在了旧位置，而我们又贴到干净底图上，
新位置会一点阴影都没有、像贴纸。所以新增 `person_ao`：
纯 AO、不赌方向（她下方是人物衣服，方向性投影会糊成一片脏）。

### 验证方式

| 验证 | 手段 | 成本 |
|---|---|---|
| framing 准确性 | 5 张素材人工目视核对（景别/自拍/光向全部一致） | 0 |
| 自动匹配路由 | 6 张照片跑 `pick_action`，检查候选集与选中项 | 0 |
| 地面动作回归 | `step8_e2e_replay.py` 回灌已有 raw | 0 |
| Person 动作重定位 | 真实生成 `shoulder` × 2（改 contact_ratio 前后各一次） | 0.24 元 |
| 上半身假设证伪 | 真实生成 `peek` × 1 | 0.12 元 |

合计 0.36 元。**先用回灌工具验证零成本的链路改动，只在"必须看模型画什么"时才烧图。**

### 遗留

1. `peek` 的锚点也是肩膀，语义是"扒着肩从后面探头"，但模型画出来更像"贴在肩旁"。
   目前靠 `contact_ratio=1.0 + anchor_edge=top` 把她的底边压在肩线上，
   视觉上成立但还不是真正的"从后面探头"——需要遮挡关系，属 P2 之后。
2. 水平位置写死"肩膀外侧 22%"和"腿左侧"。等 `place` 字段（left_of / right_of /
   on_top / in_front）补齐后应该按锚点几何算，而不是写常数。
3. `has_prop` 已经在画像里了，但还没有物件分支消费它。

## 八、实施记录（P2：seat_plane 物件路线）

### 做了什么

1. `Action` 新增 `anchor_kind`（person_part / seat_plane / vertical_prop / horizontal_edge / ground_plane），
   与 `support` 正交——"站在人物腿边"是 `anchor_kind=person_part` + `support=ground`。
2. 新增**一个**动作 `seat_edge_sit`（坐边缘垂腿），`support="object"`，`anchor_kind="seat_plane"`。
   沙发、长椅、椅子、桌沿、床沿在几何上是同一件事（水平面前沿 + 双腿垂下），
   差异只在名词，用 `{anchor}` 占位符在运行时替换成实际物件名。
3. 二级检测 `vlm_props()`：只在 `has_prop=true` 时才发，避免拖累本来准确的框。
4. 路由 `available_actions()`：人物优先 → 物件兜底 → 都没有返回不可用原因，
   `run()` 在**生成前**就退出，省一次图像费用。
5. pipeline 新增 `support="object"` 分支；`build_companion_prompt` 新增 `empty_scene`。

### 过程中踩的四个坑

**坑一：问"坐垫顶面的外接框"，模型框到了沙发 + 前面的茶几**

第一次返回 `[181,447,735,873]`，底边落在沙发底部（接近地面）。按那个框坐下去，
人坐在地板上。加宽高比校验后，模型把沙发拆成两半，两块还是太方——**所有结果都被判死**。

根因：俯视角下"水平面"在画面里会拉得很高，模型没法用矩形稳定表达。
改成**只问三个数**（前沿左右端点 x1/x2 + 竖直位置 y），单值问题，歧义小得多。

**坑二：三数版本的 y 也偏低**

模型给 y=800，实际坐垫前沿在 380~420（我在图上画了归一化标尺量的）。
它把"前沿"理解成了"整张沙发最外最靠下的边"。

改问**坐垫朝外那一面（竖立面）的框，取上沿**——这个面在照片里是明确的条纹布带。
改完后 y≈445~483，误差缩到 30~60 个单位（约 3%~6% 画面高），可用。

教训：**别只看数字"像不像"，要在图上画标尺量**。我第一次目视核对时觉得
735 那条线"差不多"，其实是差了一倍。

**坑三：JSON 缺逗号导致正则兜底失效**

模型吐出 `{"props": [{"kind": "sofa", "seat": [373, 483 934 985]}]}`——少了一个逗号。
数字全对，但我的正则兜底要求 `\d+\s*,\s*`，接不住，整条路线返回空。
改成逗号可选 `\d+\s*,?\s*`。

**坑四：模型画了两个小人**

空沙发第一次生成，画面里出现一大一小两个鲸鱼娘，差分掩码把两只都算进 alpha，
贴回去画面上有两个。两个是**连在一起**的（小的压着大的发梢边缘），
最大连通域去不掉。

根因是提示词：不管什么照片都用「图1是一张真实的人物照片」开头，
但物件路线的照片里根本没有人物，模型像是要"补一个人物进去"。

修法：`empty_scene` 单独一套措辞——不说"人物照片"、不说"和画面中的人物…"、
不要求"人物保持原样"；并把"只画一个"写成**正向的数量要求**（"画面里恰好一个角色"），
而不是"不要画两个"。改完后只出一个。

### 尺度：放弃了"座面宽度当尺子"

第一版用 `座面可见宽度 × 每小时家具系数`。同一个模型两次调用，一次框到整条沙发
（1198px）算出 186px，一次只框了沙发一段（425px）算出 66px——**小到看不见**。
"框多长算一段坐垫"没有客观边界，这个量本身不稳定。

改成**按画面高度取经验比例**（沙发 0.20、椅 0.22…，夹在 12%~26%），
并写清依据与局限：没有人物时照片里本来就没有绝对尺度参照，
不假装能烧出厘米数。真正的修法是给一个可靠物理参照，等有了再改。

### 鲁棒性：路由失败自动换线

`vlm_profile` 判"有没有人物"会假阳性——同一个空沙发照 4 次里有 1 次报成"半身人物"。
一旦走错路线，候选全是"贴人身上"的动作，模型会回一句"没有可依附的部位"。

这个信号本身有价值：它在说"路线选错了"。所以：
- `vlm_match_action` 把 `action_id="none"` 当成合法信号（`no_fit`），不再当解析错误；
- `pick_action_v2` 收到 `no_fit` 就换另一条路线再问一次（只在失败时发生）。

### 验证

| 项 | 手段 | 结果 |
|---|---|---|
| 物件检测 | 5 张无人室内照 | 沙发/餐桌椅可用；床（贴边）、台面、书桌被正确判为不可用并给原因 |
| 路由 | 11 张照片 | 有人物 6 张全走人物路线；u02/u03 走物件路线；3 张正确拒绝 |
| 物件生成 | 真实生成 ×3（0.36 元） | 最终版：单人、坐在沙发贵妃位、比例合理 |
| 人物路线回归 | 回灌工具 | `x0.628 / ground_full / 接触带 17.9`，与改动前一致 |

### 遗留

1. **座位前沿 y 系统性偏低约 3%~6%**，她坐得略陷进坐垫。真实生成看着还行，
   但换到高靠背沙发或低矮长凳上会放大。
2. `seat_edge_sit` 仍是 tier B，只验证了沙发一种家具。长椅（板条、有扶手）、
   桌沿（可能挡腿）、床沿（软塌）都还没实测。
3. 物件路线还没有"被家具遮挡"的处理：她现在永远贴在最前面，坐进沙发深处不可能。
4. `run()` 里的路由没有 `pick_action_v2` 那套换线重试，假阳性时会走错路线。

## 九、seat_edge_sit 实测定档：B → A

### 结论

**不是"只适配软质座面"。** 软硬两类都成立，关键条件不是材质，而是
**座面有没有一条清晰的横向前沿线**。

| 座面 | 材质 | 景别 | 结果 |
|---|---|---|---|
| 布艺沙发（贵妃位） | 软 | 中景 | 臀底落前沿、双腿垂下 ✅ |
| 木板条公园长椅 | 硬 | 中景 | 臀底压座板、腿垂在板外 ✅ |
| 原木桌沿 | 硬 | 近景特写 | 臀底压桌沿、腿垂在桌面前立面外 ✅（需近景补偿） |

定级 `A`，note 里写死了限定条件：座面必须有清晰横向前沿线；
近景（座面占画面宽 >60%）靠第二把尺子补偿，再近到只剩桌角会偏大。

### 测试素材是生成的

素材库里的长椅要么被裁掉（s02_park）、要么被猫和树挡住（u08_cats），
桌沿则没有干净样本。用图像生成补了两张（1536×1024，写实手机照片风格）：
- 公园木板条长椅，正面视角，无人
- 原木餐桌一角，前沿平直、下方通透，无人

两张都是"标准样本"：座面前沿线在画面里是一条干净的水平线，
正好用来验证几何，而不是被杂乱的遮挡干扰。

### 新发现一：硬座面的座面线比软座面准得多

同一套"坐垫朝外竖立面框取上沿"的问法：

- 公园长椅：命中 y=623，红线和座板前沿**完全重合**
- 原木桌沿：命中 y=395，红线和桌面棱**完全重合**
- 布艺沙发：y=445~483，比真实前沿低 30~60 个单位

原因很直观：硬座面有**明确的棱**（木板边缘、桌板棱），软座面的前沿是
布料的转折，边界模糊。所以这个方案在硬质家具上反而更可靠。

### 新发现二：同一个画面，PNG 能检出、JPEG 检不出

桌沿那张先失败了一次，报"没有可用的座面"。查下来：
PNG 原图 → `{"props": [{"kind":"table","seat":[0,395,999,490]}]}`
同一张转成 JPEG q95 → `{"props": []}`

两次请求的字节几乎相同（`image_path_to_data_uri` 都会重编码成 JPEG q92、长边 640），
所以不是编码问题，是模型**判在决策边界上**：一张占满画面的桌面特写，
"这算不算一个能坐的物件"本身就是模糊的。

修法：在 PROP_SYS 里明确写「桌子、台面的边缘同样可以坐」「即使是近景特写、
只看到桌面一角也要报出来」「不要因为"这张照片看起来不像能坐人"就不报」。
改完后 JPEG 输入 3/3 稳定检出。

**这条是召回问题，会直接影响可用率——不能只测一次就下结论。**

### 新发现三：近景特写必须用第二把尺子

只用"占画面高度比例"（table 0.20）算出 193px，而那张照片里**桌板本身就有 90px 厚**
——她只比桌板厚两倍，读起来像贴纸，完全看不出在"坐"。

改用「画面比例」与「座面宽度 × 系数」取较大值后得到 333px，
腿和鞋清楚地垂在桌面前立面外，读感才对。

但第二把尺子**只在特写时启用**（座面占画面宽 >60%）：长椅、沙发那些中远景，
画面比例已经验证过是对的，不能拿不稳定的座面宽度去动它
（同一张空沙发两次调用座面宽 425 / 1198）。

### 附带修的两处

1. **「座面贴到画面边缘」不再否决**。公园长椅、长餐桌经常从画面左沿一路到右沿，
   这是正常构图。改成在放置时把落点夹进画面内（`half + 6` 为界），
   比直接判死合理。
2. `run()` 新增 `force_route`。两个用途：用户明确要"坐家具"时即使画面有人也走物件路线；
   自动判定假阳性时给上层一个手动兜底。传 `object` 时无条件调用物件检测。

### 仍然没解决的

1. **姿态**：模型画的总是"站立的 Q 版"，不会真的屈膝。靠 `contact_ratio=0.62`
   把她沉到座面线以下，让腿垂出去——几何对，但不是真的坐姿。
2. **接触阴影偏弱**：`person_ao` 只是纯 AO，在浅色桌面上几乎看不出来，
   她仍有一点"贴纸感"。
3. **kind 分类不可靠**：石凳、木条凳、餐桌全被标成 `chair`。
   几何（x1/x2/y）稳定，但种类会错，导致 `SEAT_H_FRAC` 取错系数（误差约 ±10%）。
4. 扶手遮挡：三张样本都没扶手。有扶手的椅子/长椅上她会和扶手穿模，未验证。

## 十、姿态族（蹲/跳/盘腿坐）与接触阴影增强

### 一、几何模型补上的第三个维度：lift_ratio

原来只有两个量描述"她怎么落在锚点上"：

- `contact_ratio`：接触点在她**自身高度**的哪个位置（0=头顶，1=bbox 底边）
- `anchor_edge`：用锚点框的哪条边当她 bbox 的底边

这两个够描述"站"和"坐"，但描述不了"跳"——**因为跳的接触点不在她身上**。
她悬在半空，bbox 底边离地还有一段，而阴影必须落在地面。

所以新增：

```
lift_ratio  她的 bbox 底边离锚点线还有多远（相对自身高度）
           0 = 脚/臀紧贴锚点线（站、坐、蹲）
           0.30 = 跳起来，底边离地 30% 身高
```

`lift_ratio` 一开，落点和阴影**必须分开算**：

| 量 | 谁用 | 站/坐/蹲 | 跳 |
|---|---|---|---|
| `bottom_y`（落点） | 贴图 | 锚点线 | 锚点线 − lift |
| `contact_y`（阴影） | 阴影 | 同锚点线 | **仍然是锚点线** |

这就是跳起来那张的关键：落点抬上去，阴影留在地上。若两者混用，
会出现"人在半空、影子粘着她的脚"，比不画影子还假。

### 二、蹲姿的尺度：又一个被推翻的直觉

第一版给蹲姿的 `scale_ratio` 设成 0.19（理由是"蹲下去身体压缩、bbox 变矮"），
结果三个姿态并排时她的头明显比别的小一圈。

量了一下 raw 里的包围盒：

| 姿态 | raw bbox 高 |
|---|---|
| 蹲 | 691 |
| 跳 | 639 |
| 盘腿坐 | 696 |
| 站（基准） | 727 |

**差 5% 以内。这个模型不会因为蹲下就把人画矮**，它画的是一个"腿部折叠、
但整体尺寸不变"的 Q 版。所以给小系数只会把同一个角色渲染成更小的一只。

统一改成 0.26（和 `leg_hug_knee` 同档）后，三个姿态头部尺寸对上了。

**这是本轮第二次"我以为模型会那样、其实不会"**（上一次是"上半身动作模型能画对"）。
规律很清楚：**凡是对模型行为的先验判断，都要用 raw 量一遍再定参数。**

### 三、接触阴影增强

#### 问题一：AO 是个大软椭圆，没有"接触"这个概念

`render_shadow_matte` 的 AO 层长半轴 0.42w、sigma 0.03w、透明度 0.60。
它表达的是环境光遮蔽这一层**低频**信息，方向上是对的，但它不区分"她碰到哪儿"。

真实照片里让物体看起来"压在上面"的，是接触处那条**又窄又深的暗线**
（几何上接近零距离遮蔽，只有几像素宽）。缺了它，AO 再强也读成贴纸。

新增 `contact_core()`：用她自己的掩码在接触线附近的**水平占据范围**生成暗带，
沿 y 做高斯衰减。所以站着是两小块鞋底、坐着是臀底一长条、跳起来是零——
不需要为每种姿态写参数。

#### 问题二：坐姿的接触点取错了

原来不论姿态都用 `bb[3]`（包围盒底边）当接触点。对站姿对，
但 `contact_ratio=0.62` 的姿态，她的**脚是悬空的**，接触点在身体 62% 处。

实测坐肩那张，量化对比：

| 区域 | 增强前 | 增强后 |
|---|---|---|
| 接触线（臀底 y≈702） | 暗 19 | **暗 82** |
| 她的脚底（悬空 y≈840） | 暗 41（错的） | 暗 10 |

阴影从悬空的脚移到了真正的接触点。

#### 问题三：搬动过的角色，AO 太弱

`min(intensity,0.55) × 0.85` 在浅色桌面上几乎看不出来。改成
`min(intensity+0.15, 0.75)`，不再打 0.85 折。

#### 暗核的一个坑

第一版暗核返回空——因为掩码底边在 1660，而地面线在 1681。
她白色鞋底不是蓝色主导，被 `character_mask` 漏掉，掩码比真实轮廓短 20px。
搜索带只扩 ±t（13px）时一个像素都搜不到。
改成向上扩 3t 才拿到她的横向占位。

### 四、验证（全部用回灌，0 元）

| 项 | 结果 |
|---|---|
| 地面·坐地抱膝 | `ground_full+core`，脚下出现贴轮廓暗带 |
| 人物·坐肩 | `person_ao+core`，阴影从脚移到臀底接触线 |
| 物件·坐沙发 | `person_ao+core`，座面上出现接触暗带 |
| 悬空·跳 | `ground_full`（**无** core），地面带暗 54、身后空隙只暗 8 |

真实生成 3 张（蹲/跳/盘腿坐）共 0.36 元，其余全部回灌。

### 五、遗留

1. 蹲姿那张她更接近"跪"——膝盖着地而非双脚踩地。`contact_ratio=1.0` 让最低点
   落在锚点线上，几何没错，但"蹲"的姿势本身模型画得偏向跪。
2. `contact_core` 目前只沿水平方向取占据范围，遇到"两条腿分开"的站姿会连成一条
   横贯的暗带，中间的空隙也被压暗。严格做应该按连通段分别画。
3. QC 指标 `contact_band_delta` 对悬空姿态失效（采样带落在空气里），需要按
   `lift` 修正或换指标。

## 十一、修复「她身上有透明的部分」

### 现象

用户反馈：小鲸鱼身上有透明的部分，不完整。缩略图上看不出来，放大后能清楚看到
**大腿上有一块灰色**（背景色透过来）、裙摆下缘发虚、腿和鞋像被擦掉了一部分。

### 根因

`_alpha_in_box` 用 **`|raw - 场景| > 45`** 判"这块是不是她"。

阈值 45 是为了保住**外轮廓**不沾背景——模型每次都会把整张图轻微重绘一遍，
背景的差分幅度在 14~30 之间，阈值低了边缘就会拖一圈脏。

但这个阈值对**她身体内部**太高了。有些地方她与底图的差异不足 45：

- 深藏青裙摆压在阴影里（两边都很暗，差值小）
- 白围裙压在亮地面上（两边都很亮，差值小）
- 蓝色头发的渐变过渡区

这些像素 alpha 归零 → 贴回干净底图时**背景透过来** → 看着是半透明的。

**量化**：蹲姿那张，不透明像素里有 **15.5% 是内部空洞**；跳姿 21.1%，盘腿 18.8%。

### 修复：两级阈值 + 只填封闭空洞

外轮廓继续用高阈值 `m`；内部用低阈值 `low`（22）补，**但只补被她轮廓围住的封闭区域**。

"封闭"这个限定是走了两次弯路才定的：

| 方案 | 结果 |
|---|---|
| `low ∩ 凸包` | 凸包在凹形处过宽（呆毛到右侧头发之间整片三角都在包内），她头顶右边多出一条横贯灰线 |
| `low ∩ 行内跨度` | 腿上的洞补好了，但她就坐在长椅上，那一行装的全是长椅 → **把木板条和螺栓一起贴了过来** |
| **只填封闭空洞** | ✅ 她的腿、裙摆、围裙都是被自己围住的；长椅、地面、背景都与画面边缘连通，不会被算成洞 |

实现：从裁切框**四条边界**泛洪（不是四角，四角太容易漏），泛到的是"外部"，
剩下的空白就是内部洞。降采样到 200 宽再做——她身上的洞都是大块，缩小不影响判断，
而 PIL 的 `floodfill` 是纯 Python 循环，全分辨率太慢。

### 修复前后（内部空洞占比）

| 姿态 | 修复前 | 修复后 |
|---|---|---|
| 蹲 | 15.5% | 7.6% |
| 跳 | 21.1% | 17.5% |
| 盘腿坐 | 18.8% | 9.8% |
| 坐肩 | 14.3% | 9.3% |
| 坐沙发 | 6.8% | 2.7% |
| 坐地抱膝 | 14.3% | 5.7% |
| 长椅 | 15.1% | 13.6% |
| 桌沿 | 2.6% | 2.5% |

剩下的百分之几主要是**手臂与身体之间、双腿之间**这类合法的凹形空隙，
不是洞。（这个"行内空隙"指标本身会把这些算进去，所以只能横向比、不能当绝对值看。）

代价：`_alpha_in_box` 从约 0.15 秒变成 0.85 秒。相对 15 秒的生成可以接受。

### 顺手修的一个硬伤

`has_prop` 这个布尔会误判为 false——同一张公园长椅照、同一张桌面特写，
都有过"明明有座面却答没有"。而它一旦为 false，整张照片会被直接判"不可用"。

改成：**没人物的照片一律调一次物件检测**，不再先看 `has_prop`。
多花约 1.5 秒，换掉一个"整张照片报废"的失败模式。

### 遗留

1. **长椅那张仍有横木碎片**：她身下的长椅被模型重画过（遮挡、投影），
   那部分差分为高分、且与她相连，会被当成她一起抠出来。
   A/B 确认这是**既有问题**，不是本次改动引入的。
   要修需要引入"颜色/形状先验"或"她只能是一个连通的人形"这类约束。
2. 阈值 22 是经验值。坐白色沙发、白色床单上时她与背景更接近，
   可能需要按局部对比度自适应。

## 十二、为什么需要抠图？（对架构的一次质疑）

用户问：**为什么需要抠图？这个 bug 是加强阴影导致的吗？**

### 先说不是阴影

alpha 在阴影**之前**就算完了。`contact_core` 只做乘法变暗，`defringe` /
`match_ambient` 只改 RGB，三者都不碰 alpha。阴影不可能产生透明。
这个可以用代码顺序直接否掉，不需要实验。

### 抠图为什么存在

因为要在生成之后改她的**尺寸**。

模型对绝对尺寸的控制误差是 1.5~4 倍，而且是**随机**的（同一提示词不同 seed 差一倍）。
文字约束（"约40厘米""像玩偶挂件那么大"）实测无效——这是最早几轮就证伪的东西。

要改尺寸，就必须把她"从图里拿出来"重新采样再放回去，也就是必须抠图。

### 但这是架构错位

**抠图本该是补救手段，现在成了默认路径。**

而抠图绕不开一个判断："哪些像素是她"。这个判断在两个颜色相近的地方必然出错：

- 深藏青袖子压在蓝色牛仔裤上（两边都暗、都偏蓝）
- 白围裙压在亮地面上（两边都亮）
- 蓝色头发压在阴影里

出错的表现就是**透明**（背景透出来）或**缺块**（连边界一起切掉）。
今天修的"内部空洞"是其中一类，还有别的（见下）。

### 今天做的实验：能不能不抠？

思路：**在输入图里画一个灰色剪影占位符，让模型照着填**。如果模型肯照做，
尺寸位置在生成时就对了，抠图整步可以删掉。

用她自己的真实轮廓（从一张已有 raw 里取出的 alpha）做成剪影，加绿色描边，
贴在目标位置/尺寸上，再让模型"把这个剪影填成这个角色"。

结果：

| 方案 | 底边误差 | 中心 x 误差 | 高度误差 |
|---|---|---|---|
| 纯文字（现行） | 数十~数百 px | 数十~数百 px | −40%~+120% |
| 灰色椭圆占位 | **0 px** | −58 px | +56% |
| 真实剪影占位 | **−2 px** | +14 px | +51% |
| 真实剪影 + 预缩 1.5× | +6 px | −12 px | **+70%** |

两个结论：

1. **占位符能定住位置**，误差从几百像素降到 10 像素级。这一条很硬。
2. **定不住尺寸**。而且预缩占位符反而更差（+51% → +70%），说明模型不是线性缩放，
   它有一个"最小尺寸"的倾向——她是个大头大尾巴的 Q 版，视觉体量超过剪影框，
   模型会按"身体装进去、头发尾巴溢出来"来画。

所以**短期内抠图还得留着**，至少要用来改尺寸。

### 剩下真正没解决的（诚实清单）

1. **长椅那张的木板碎片**：她身下的长椅被模型重画过（遮挡、投影），
   那部分差分是高分、且与她**相连**，被当成她一起抠出来。
   画面上就是她腰侧多出几条木板条和螺栓。这是目前最明显的"不完整"。
   A/B 确认是既有问题，不是最近改动引入的。
2. **蹲那张左侧头发有一道直切口**：alpha 边界在低反差处直接切断。
3. 上面两条的共性：**都是"抠图边界"问题**，不是"抠图之后"的问题。

### 建议的下一步（待定）

| 选项 | 做法 | 代价 | 收益 |
|---|---|---|---|
| A | 给 alpha 加"她必须是单一连通人形"约束（形态学开运算 + 只保留最大块 + 与核心蓝色掩码的连通性） | 中 | 直接消掉长椅碎片 |
| B | 占位符定位置 + **只做原地等比缩放、不搬移** | 中 | 位置不再引入误差，出错面减半 |
| C | 占位符 + 多次生成挑最接近目标尺寸的一张 | 低（费钱） | 绕开"改尺寸"这一步，彻底不抠 |
| D | 抠图结果人工确认（UI 里让她可拖动/可缩放） | 低 | 兜底，但把问题推给用户 |

我的倾向：**先 A（消掉最刺眼的长椅碎片），再 C 的方向试一次**——
如果占位符 + 两次生成能稳定落在 ±15% 内，那"抠图"就可以只在超差时才触发，
成为真正的补救路径。

## 十三、架构转向：把角色和场景解耦（用户提议，已验证）

用户提出：**先根据场景图生成一张简易图，再在它上面生成一张背景透明的鲸鱼娘，
这样就可以自由缩放并放到正确的位置。**

这个方向是对的，而且比现行架构好一个量级。下面是验证结果。

### 为什么原来的路走不通

在**真实照片**上判断"哪些像素是她"，这个判断在两个颜色相近的地方必然出错：

- 深藏青袖子压在蓝色牛仔裤上
- 白围裙压在亮地面上
- 蓝色头发压在阴影里

出的错就是透明（背景透出来）和缺块（边界被切掉）。修了两轮阈值、凸包、封闭空洞，
最好也只到 5~7% 的内部空隙。

### 新路的关键优势：判断退化了

白底抠图的判据变成：

> **近白 且 与画面边界连通** 的像素才是背景

她的白围裙、白袜、白荷叶边都被深色描边围住，**不与边界连通**，所以不会被误删。
歧义从"这块像素是不是她"降级成"这块像素是不是白的且连着边"——几乎不可能错。

实测对比（同一姿态、同一角色）：

| | 内部空隙 | 备注 |
|---|---|---|
| 照片上抠图（现行） | **7.61%** | 头发里嵌着背景纹理、裙摆底下混着地砖 |
| 白底立绘抠图（新） | **1.80%** | 边缘干净，白围裙/白袜完整 |

视觉对照更能说明问题：把两者的 alpha 铺在棋盘格上，左边能明显看到她身上
"嵌着"照片的背景，右边只有她。

### 顺带解决的三件事

1. **尺寸**：直接 resize，无损、可控、精确。不再需要"用人物身高推算目标高度"
   这种间接控制。
2. **位置**：完全由程序计算，模型不参与。
3. **复用（最大的一笔）**：立绘**与照片无关**。同一个姿态只需要生成一次，
   之后可以贴到任意照片上。

   | | 现行 | 立绘路线 |
   |---|---|---|
   | 每张照片的生成成本 | 0.12~0.30 元 | **0** |
   | 每张照片的等待 | 15~70 秒 | **< 1 秒**（纯 CPU 合成） |
   | 角色总生成次数 | 照片数 | **姿态数**（9 个） |

   也就是说：9 个姿态各生成一次（约 1.1 元），之后所有照片都是**零生成成本、亚秒级**。

### 代价（必须承认的两条）

1. **光照是通用的**，不来自照片。要靠 `match_ambient` 做环境色匹配 +
   程序化阴影贴合。比模型自己在场景里画出来的融合度差一些。
2. **没有遮挡关系**。她不能被人物的手臂挡住一半、不能从衣摆后面探头。

第 2 条决定了适用范围——按"是否需要遮挡"分两条路线：

| 路线 | 适用动作 | 理由 |
|---|---|---|
| **立绘路线** | 站在腿边、蹲、跳、盘腿坐、坐长椅/沙发/桌沿 | 她是一个完整的、独立的人形，没有东西挡她 |
| **场景内路线**（保留现行） | `hem_peek`（扒衣摆）、`peek`（扒肩探头）、`shoulder`（坐肩） | 必须有遮挡：下半身被布料挡住、身体被头肩挡住 |

### 已落地的代码

`s3/sprite.py`：

- `build_sprite_prompt(action_desc)` —— 姿态描述**直接复用动作库的 desc**，不另写一套
- `key_white(img)` —— 白底抠图，`thr=232`、`feather=1.2px`
- `_flood_from_border(free)` —— 自实现的 numpy 泛洪
- `trim(rgba)` —— 按 alpha 裁掉留白，让宽高比就是她真实的宽高比
- `sprite_path/load_sprite/save_sprite` —— 立绘缓存（按 动作×模型 命名）
- `alpha_hole_ratio(rgba)` —— 诊断用，横向比较抠图质量

**一个隐蔽的坑**：`PIL.ImageDraw.floodfill` 在 1024×1536 上会**静默失效**——
同样的调用在 10×10 小图上正常，大图上返回时一个像素都没改，也不抛异常。
第一版白底抠图因此把整张图都当成角色（不透明 100%）。改用 numpy 迭代膨胀解决。

### 迁移建议

1. **立绘路线先覆盖"独立人形"的动作**（站/蹲/跳/坐），这些占日常使用的绝大多数。
2. 遮挡类动作保留场景内生成，它们本来就只有 3 个。
3. 立绘按 `动作 × 模型` 缓存到 `assets/sprites/`，生成一次长期复用。
4. 光影融合是这条路线的短板，`match_ambient` 和接触阴影要跟着加强——
   这一步没做好，她会看起来像贴纸。

## 十四、立绘路线落地

### 一、动作库加一条"渲染路线"维度

```
Action.render  "sprite" | "scene"
```

判据只有一条：**她需不需要被场景里的东西挡住**。

| render | 动作 | 为什么 |
|---|---|---|
| `sprite` | leg_hands_behind / leg_hug_knee / crouch_by_leg / jump_air / sit_cross_legged / seat_edge_sit | 她是完整独立的人形，没有东西挡她 |
| `scene` | shoulder / peek / hem_peek | 必须被挡：下半身藏在衣摆后、身体藏在头肩后、坐在肩上时被衣服压着 |

`sprite` 6 个，`scene` 3 个。

### 二、立绘是**一次性基建**，不是每次请求都做

`tools/build_sprites.py`：给所有 `render="sprite"` 的动作各生成一张白底立绘，
抠图后缓存到 `assets/sprites/{动作}__{模型}.png`。

实测 6 张一次跑完，每张 10~16 秒：

| 动作 | 抠图内部空隙 |
|---|---|
| leg_hug_knee | 1.9% |
| crouch_by_leg | 1.8% |
| sit_cross_legged | 2.1% |
| leg_hands_behind | 2.4% |
| seat_edge_sit | 4.3% |
| jump_air | 4.5% |

全部低于"在真实照片上抠"的最好成绩（7.6%）。

### 三、`run_sprite()`：无生成的合成路径

`run()` 在入口按 `Action.render` 分派：

- `render == "sprite"` → `run_sprite()`，**不调图像生成**
- `render == "scene"` → 原来的生成 + 抠图路径

`run_sprite()` 的步骤：

1. `vlm_profile()` 拿景别/人物框/腿框/光向（1 次调用）
2. 需要时 `vlm_props()` 拿座面（无人物的照片）
3. `_sprite_placement()` 算出目标高度、中心 x、底边 y —— **复用和场景路线完全一样的落点规则**
   （人物身高 × scale_ratio / 座面宽度两把尺子 / contact_ratio / lift_ratio）
4. `load_sprite()` 取缓存（没有就现生成一次）
5. resize + paste + `match_ambient` + 接触阴影 + AI 标识

返回结构与 `run()` 对齐，前端不用区分两条路。

### 四、实测

| 场景 | 路线 | 耗时 | 阴影 |
|---|---|---|---|
| 户外全身照 · 蹲 | sprite（缓存） | 5.8s | sprite_full+core |
| 户外全身照 · 跳 | sprite（缓存） | 5.0s | sprite_full（无 core，悬空） |
| 户外全身照 · 站腿边 | sprite（缓存） | 4.6s | sprite_full+core |
| 户外全身照 · 盘腿坐 | sprite（缓存） | 7.0s | sprite_full+core |
| 公园长椅 · 坐边缘 | sprite（缓存） | 6.2s | sprite_ao+core |
| 餐桌 · 坐边缘 | sprite（缓存） | 5.4s | sprite_ao+core |
| 空沙发 · 坐边缘 | sprite（缓存） | 8.5s | sprite_ao+core |

**5~8 秒**，其中图像生成为 0。剩下的时间全在两次 VLM 分析上——
**瓶颈从"生成"变成了"看图"**。下一步该做的是把 `vlm_profile` 和 `vlm_props`
合成一次调用，或者缓存分析结果。

### 五、这条路的短板（现场看到的）

1. **她是平的**。立绘是中性棚拍光，贴到强侧光的户外照上会显得像贴纸。
   `match_ambient` 只做整体色偏（实测位移只有 [-1.7, -8.3, -8.3]），
   补不了方向性的明暗。要做得好，需要按光向给她加一层亮度梯度——
   这是"重打光"，不是"调色"。
2. **尺度还需要再校**。长椅那张高 201px（画面高的 18.6%），偏小；
   餐桌那张 353px（32.7%），偏大。原因是 `SEAT_H_FRAC` 是按"家具占画面多大"
   估的经验值，换一批素材就漂。
3. **没有遮挡**。这是路线本身的边界，不是 bug。

### 六、下一步建议

1. **把两次 VLM 合成一次**（景别 + 人物框 + 腿框 + 光向 + 物件框），
   目标是把 5~8 秒压到 2~3 秒。
2. **重打光**：按 `LightingState` 的方向给她叠一层线性亮度梯度（±10%~15%），
   比调色更能解决"贴纸感"。
3. `SEAT_H_FRAC` 改成用"座面高度 / 画面高"这种有物理含义的量，
   而不是拍脑袋的常数。

## 十五、修「她身上那条横线」：接触暗核的作用域错误

### 一、现象

用户发来 `output/step8/sprite_object_route.jpg`（长椅 / 餐桌 / 空沙发三联），
三张图里**她身上都有一条横贯的灰线**，位置在身体 62% 高度附近。

这是"接触阴影增强"那一轮引入的**回归**——`contact_core` 是那轮新加的函数。

### 二、定位：暗带压在她身上

用长椅那张量化，取 `placement = {box:[457,512,138,203], contact_y:637}`：

| 采样位置 | 成品亮度 | 原图亮度 |
|---|---|---|
| 她身上 接触线上方 5px（y=632） | **87.5** | 134.9 |
| 她身上 接触线 ±2px（y=637） | **71.2** | 131.0 |
| 她身上 接触线下方（y=667） | 192.2 | — |

接触线附近她被压暗到 71（原图 131），上下都正常 → 一条横带。

根因在两行：

```python
cols = band.any(axis=0)          # "她在接触线附近占了哪些列"
dark[:, cols] = prof[:, None]    # ← 整列都压暗，包括她自己
```

`cols` 回答的是"哪些列有她"，被当成了"这些列整列都该压暗"。
**作用域写错**。坐姿的接触线恰好就是臀底，暗带直接穿身。

物理上也讲不通：被遮蔽的是**受光面**，不是遮挡物。

### 三、修法（三层，缺一不可）

1. **她身上清零**：`dark[_dilate1(mask)] = 0`。
   膨胀 1px 是为了吃掉抗锯齿的过渡像素——压暗它们会在轮廓上留一圈描边。
2. **横向也做高斯**（`hprof`）。原来只在 y 上做高斯、x 上一刀截断，
   暗带其实是个**硬边矩形**。座面路线看不出来（大半被她挡住），
   落到地面姿态就现形：人行道上横着一条硬边暗条，比原 bug 还显眼。
   做法是把"她占了哪些列"当成一维信号做高斯模糊，两侧平滑衰减。
3. **立绘路线改用精确 alpha**。`run_sprite` 本来有立绘的 alpha 和贴图位置，
   却去调启发式的 `character_mask`（蓝色主导 ∩ 差分）。她的白肚皮、白鞋底
   不在里面 → 那些像素被当背景压暗。现在直接从 alpha 取，逐像素准确。
   照片路线拿不到 alpha，保留 `character_mask` 算范围、额外传
   `protect=change_mask(...)` 兜底清零（宁大勿小，最多暗带画不出来）。

配套：纵向剖面改成非对称——接触线上方 sigma=0.35t（只为消硬接缝），
下方 sigma=1.0t（受光面上真实存在一段暗部）；横向外扩 `spread_ratio=2.5`（单位 t）。

### 四、怎么证明修掉了（可判定的断言）

不用眼睛判断"看起来还有没有线"，用一条能自动化的断言：

> **带暗核的成品，在她自己的身体像素上，必须和"完全不画暗核"的成品一致。**

暗核的语义是"接缝处的受光面变暗"，她本人不在受光面上。
`experiments/step10_contact_core.py` 实现了这条：

```
[长椅] 她身上 |旧-无核| = 23.16   →  |新-无核| = 0.31   OK
[餐桌] 她身上 |旧-无核| = 22.55   →  |新-无核| = 0.19   OK
       座面上 峰值压暗 39~55 灰阶 / 877~2216 px   ← 暗核仍在工作
```

地面姿态同样回归（`crouch_by_leg` / `sit_cross_legged` / `leg_hug_knee` /
`jump_air`）：四者 |新-无核| 均为 0.00~0.02；`jump_air` 因为悬空，正确**没画**暗核。

**这一步踩过一个坑**：第一次跑出 `|新-无核| = 32` 的假失败。
原因是三次运行各自调了一次 VLM，同一张餐桌照 `none` 那次判成有方向光
（`sprite_full`）、`new` 那次判成无方向（`sprite_ao`），两层 AO 根本不是一个东西。
后面所有 A/B 都必须**冻结 VLM 输出**，让唯一变量是被测的那一项。

### 五、顺手修掉的健壮性问题

`_sprite_placement` 在物件路线但 `usable` 为空时是 `IndexError`（列表取 `[0]`），
调用方拿到的是 traceback 而不是"这张用不了"。VLM 确实会偶发返回 0 个可用座面
（同一张长椅图，之前几次都给框，某次就是空）。改成 `ValueError` + 友好文案，
`run_sprite` 捕获后返回 `{"error": ...}`。

### 六、还没解决的

- **照片路线的兜底是粗的**：`change_mask` 在 256 宽上算完再放大，边缘准到 ~6px，
  而暗核只有 ~7px 厚。它能保证"不画到她身上"，但暗带的位置会比立绘路线糊。
  场景内路线已经是次要路径（架构已转向立绘），暂不投入。
- **暗核和 AO 的强度配比没有标定**。现在横向一散，峰值从 86 掉到 ~42 灰阶，
  压住她的力量弱了。等"重打光"做完一起在一批金标准上回归。

## 十六、重打光：从"她是平的"到"她服从这个场景的光"

### 一、要解决的问题

立绘是在纯白背景、中性棚拍光下生成的。它自带一套"从正前方打光"的明暗，
贴到强侧光的照片上就穿帮成贴纸——不是画得不好，是她的明暗和照片的明暗
不是同一个光源。

`match_ambient` 解决不了这个：它只做**直流分量平移**（把她的整体色偏往背景拉），
不改变任何空间分布。实测位移只有 [-1.7, -8.3, -8.3]——"调完之后她还是平的"。
要补的是**梯度**，不是**偏移**。

### 二、模型

沿主光方向叠一层线性明暗：

    gain(p) = 1 + amp·t(p) + t(p)·tint      t ∈ [-1,1]，沿光方向在她包围盒内归一化

三个必须做对的地方：

1. **保能量**。她的轮廓在 t 上不对称（尾巴甩在背光侧），直接乘会让整体亮度漂 6%。
   按 alpha 加权的平均增益归一到 1——只改分布，不改总亮度。
2. **按 alpha 羽化**。边缘抗锯齿像素和内部一样乘会留下一道亮度台阶。
3. **色温跟着方向走**，而且不拍常数：把背景按亮度分位数切成"亮的一撮"和
   "暗的一撮"，两组色差就是这张照片光影的色温差。阴天量出接近 0，夕阳明显偏暖。

### 三、光向该信谁：**不能信 VLM**

这是这一节最重要的结论。

`s04_full`（秋季公园全身照）里，VLM 回答 `light = left`。但放大地面看：
**树影和她自己的投影都朝左倒，牛仔裤和球鞋也都是右侧更亮**——光是从右边来的。
方向判反了。

而同一张图的横向亮度差是 **+4.9%**（向右变亮），和实拍一致。

方向错了比不打光更糟，所以最终**方向由画面自己决定**：

```python
def side_light(photo):     # s3/relight.py
    每列取中位数 → 左 1/3 与右 1/3 的均值 → (右-左)/(右+左)
    |对比度| < 3% 视为"没有侧光"，返回 None
```

VLM 仍然有用：它给的 `quality_hardness` 决定梯度**幅度**，那是个不会反号的量。

**顺带发现的一个 bug**：`PROFILE_SYS` 开头写"给你一张**人物照片**"、结尾写
"如果画面里根本没有人，输出 `{"framing":"none"}`"——**无人照片直接不回光向**。
物件路线（长椅/餐桌/沙发）全是无人照，所以 `prof.light` 永远是 None。
改掉措辞、明确要求"没有人也必须回答 light 和 has_prop"之后，三张都能给出了：

| 场景 | 修前 | 修后 |
|---|---|---|
| 长椅 | （空） | top |
| 餐桌 | （空） | left |
| 客厅沙发 | （空） | flat |

### 四、为什么只补横向

纵向亮度差里**内容占比压倒性**。实测整幅平面拟合的纵向斜率：

| 场景 | x 斜率 | y 斜率 | 纵向那部分其实是 |
|---|---|---|---|
| 长椅 | −0.2% | **+63.4%** | 上方草地(暗) → 下方水泥地(亮) |
| 餐桌 | −54.4% | −1.7% | 木桌面的明暗分布 |
| 公园自拍 | +21.0% | **−78.5%** | 上方天空(亮) → 下方深色衣服(暗) |

那不是光，是"画面里什么东西在哪儿"。拿它当光向，长椅那张会被判成"光从下方来"。

而且横向恰好是**唯一需要补的**：立绘自带"正面略偏上"的烘焙明暗，顶光这一维
本来就大致对，再叠一层就是重复打光。所以顶光/散射光**故意不处理**。

### 五、幅度：硬度 × 证据强度

    amp = clip(0.10 + 0.16·hardness, 0.08, 0.24) × clip(|对比度|/0.12, 0.35, 1)

- `hardness`（光质）：硬光方向性强，明暗过渡陡。用 hardness 而不是 intensity——
  intensity 是"影子多黑"，hardness 才是"方向性多强"。
- `|对比度|`（证据强度）：四个场景差了近十倍（长椅 7%、餐桌 34%）。
  只按 hardness 给会让弱侧光场景被打上一道不该有的斜坡。
  实测："长椅 amp 0.14" → 加证据项后 0.084。

**不能直接把对比度当幅度**：那是整幅画面的左右亮度差，而她的宽度只占画面一成多，
按比例缩下去等于不打光。真实侧光在她身上的明暗来自**曲面法线**随光向变化，
不是一层横跨画面的线性斜坡。

### 六、验证

`experiments/step11_relight.py`。测的不是"她整体亮度分布"（那被她自己的画风吃掉：
脸亮裙摆暗，随便一量就是 ±0.1，和光向无关），而是**重打光到底加了多少**：

| | 光向 | amp | 受光侧−背光侧（理论） | 削顶 |
|---|---|---|---|---|
| 长椅 | 右 | 0.084 | +10.0（12.3） | 0.54% |
| 餐桌 | 左 | 0.172 | +18.2（23.2） | 0.90% |
| 客厅沙发 | 左 | 0.093 | +11.2（13.6） | 1.13% |
| 户外全身 | 右 | 0.092 | +12.6（13.9） | 0.47% |

实测约为理论的 78%~88%（保能量偏移按 gain 加权而不是按亮度加权，差值合理）。
`jump_air` 等四个地面姿态回归全部正常。

**踩过的两个坑**：
- 第一版 A/B 只替换了 `contact_core`，"关"和"开"两次重打光都生效，
  两个数一模一样（+0.248 / +0.248），差点被当成"重打光没用"。
- 用 `contrast_along` 去量"增益差"算出了 +1.8e7：那个公式是 `(hi−lo)/(hi+lo)`，
  前提是被测场非负；增益差有正有负，分母跨过 0。

### 七、性能

| 步骤 | 全画幅 | 裁到 ROI |
|---|---|---|
| `side_light` | 10ms | 10ms |
| `scene_tint` | 178ms | 34ms（跳采样 1/9 + 分位数替代排序） |
| `relight` | 345ms | **57ms**（alpha 之外本来就乘 0） |

合计 ~100ms，相对 VLM 的 5~10 秒可忽略。

### 八、还没解决的

1. **影子方向仍然用 VLM 的 left/right**，也就是还带着"s04_full 那种判反"的风险。
   重打光已经改用画面证据，阴影没改——两者现在可能不一致，这是当前最明显的一处
   内部矛盾，下一步优先处理。
2. **没有"暗面细节"**。现在只是整体压暗，真实侧光下背光侧会失去高光、饱和度下降。
   要做得更像，得把 gain 同时作用到饱和度和局部对比度上。
3. 散光和顶光的场景仍然什么都不做——这是有意的，但意味着"她是平的"在这类场景里
   没有改善。这类场景真正缺的可能是**对比度/饱和度匹配**，不是方向光。

## 十七、影子方向也改用画面证据（收掉十六节的内部矛盾）

### 一、问题

十六节把重打光改成"信画面"之后，出现了一处自相矛盾的状态：

- 她的**明暗**按 `side_light()` 走（s04_full：光从右来）
- 她的**投影**还按 VLM 的 `light` 走（s04_full：VLM 说是左边）

于是她朝右边变亮、影子却朝右躺——同一个画格里两个光源方向。

### 二、量出来的错位

用"开/关 `render_shadow_matte` 差分"把她的影子单独隔离出来，算质心相对接触点的横向偏移：

| 场景 | 光线 | 修改前质心 | 修改后质心 | 判定 |
|---|---|---|---|---|
| 户外全身 | 右 | **+62.9px** | **−34.6px** | 反了 → OK |
| 餐桌 | 左 | +92.8px | +92.8px | 本来就对，无回归 |
| 长椅 | 右 | −0.5px | −0.4px | AO only，不画方向影 |

判据只有一条：**影子必须落在背光侧**，也就是质心偏移与光来向异号。

### 三、改法

`LightingState.light_azimuth_deg` 不再只取预设，而是：

```python
shadow_az = sl["azimuth"] if sl is not None else light["azimuth"]
```

`side_light()` 量不出侧光（顶光/散射）时才退回 VLM 的标签。那时 `confidence=0`，
`render_shadow_matte` 只渲染 AO 层，方向本来就用不上，所以这个退回是安全的。

顺带把诊断字段写清楚：`shadow_azimuth` / `shadow_dir_source`（`scene_slope` /
`vlm_label` / `unused_ao_only`）。长椅那种"有方向但只用 AO"的情况单独标
`unused_ao_only`——否则日志看起来像"用了方向"，下次排查又会被误导。

### 四、自己写错又抓回来的地方

第一版实验里把 `side_light` 的返回值当成了"影子朝向"：

```python
exp = '左' if sl['azimuth'] == 0 else '右'      # ← 错
```

`side_light` 给的是**光来向**：azimuth=0 表示"右亮左暗"，即光从**右**来。
写成"左"之后，判据整体反号，s04_full 那张会得出"修改前是对的"这个完全相反的结论。

统一约定：`azimuth` 一律表示**光从哪来**，`shadow_angle_deg()` 内部 +180 转成影子方向。
实验里也只用 `light_word()` / `shadow_word()` 两个小函数转换，不再手写判断。

### 五、还没解决的

`shadow_angle_deg()` 里那 `+12°` 的地面透视偏置还是拍脑袋的常数。
它的意思是"影子随地面向灭点收"，但实际偏多少取决于相机俯角和地面朝向，
现在靠经验值。要真的算，需要灭点或地面单应——那是另一个量级的工作。

## 十八、阴影图层挪到鲸鱼娘**下面**（用户提议）

### 一、这是一次"违反自己契约"的修复

`render_shadow_matte` 的 docstring 第一句就写着：

> 合成方式：scene = scene * (1 - dark)。**角色应贴在该层之上（角色遮挡自己的影子）**。

而立绘路线的实际顺序是「先贴她 → 再画阴影」，`step = step * (1 - dark)` 把她也一起压暗了。
代码违反了自己的契约。用户提出"阴影层规定在鲸鱼娘图层下面"，指的正是这件事。

### 二、违规有多严重（量化）

"开/关 `render_shadow_matte`"两次成品差分，只看她的 alpha 内部：

| 场景 | 接触带内均值 | 峰值 | 受影响像素 |
|---|---|---|---|
| 蹲姿·地面 | 14.6 灰阶 | 158 | 16.3% |
| 坐长椅 | 13.4 灰阶 | 72 | 31.8% |
| 坐桌沿 | **27.1 灰阶** | 143 | **48.7%** |

桌沿那张接近一半的身体被 AO 椭圆压暗。最直观的是她的**白围裙被染成灰米色**。

### 三、怎么做到"在下面"而不重排整条链路

设 `B` = 干净底图，`a` = 她的覆盖度，`H` = 她（已调色/打过光）的颜色：

    result = B·(1-a) + H·a            ← 现在手上这张
    目标   = B·(1-dark)·(1-a) + H·a    ← 阴影只落在背景那一半

两式相减：**目标 = result − B·(1-a)·dark**。即从"她没盖住的那部分"里减掉阴影。
逐点核对：`a=0` → `B(1-dark)`；`a=1` → 原样；`a=0.5` → 各取一半。

好处是不用把"贴人 → 调色 → 打光 → 画影"重排成"画影 → 贴人 → …"，
也就不会碰到 `match_ambient` 拿"她外圈"当背景基准那件事
（那个圈如果先被阴影压暗，会把她也一起拉黑）。

实现：`s3/s3ops.py::shadow_under()`。

### 四、修完暴露出的第二个缺陷：AO 椭圆一直躲在她身后

把阴影挪下去之后，长椅那张的接缝带只剩 **16.7%** 的像素有可见压暗，她像浮在座面上。

原因很直接：AO 半轴 `0.42w` → 全宽 `0.84w`，**比她本人（1.0w）还窄**，
中心又正好在被她挡住的位置 → 坐姿时可见部分约等于零。
站姿没事，因为 AO 整个落在她脚下的地面上，完全暴露。

这个缺陷一直存在，只是以前那块"压在她裙摆上的 AO"冒充了接触感。
**把阴影挪到下面，等于把它揭穿了。**

修法：按"接触面以下还剩多少她"放宽 AO 半轴（`AO_SPILL_K = 0.28`）：

    hidden = (box[3] − contact_y) / (box[3] − box[1])
    a_ratio = 0.42 + 0.28 · min(hidden / 0.5, 1)

站姿 `hidden≈0` → 仍是 0.42（放宽只会让地面出现一团大暗斑）；
坐姿 `hidden≈0.38` → 0.63（全宽 1.26w，两侧各溢出约一成）。

### 五、验证

`experiments/step13_shadow_layer.py`，四条判据：

1. `mean|带影-无影|` 在她身上 ≈ 0
2. 接缝带（她轮廓外 2~10px、接触线附近）的压暗均值够大
3. 接缝带里 >8 灰阶的像素占比够高（不是几个孤点在撑）
4. 背景大片区仍有压暗（防"把 dark 整个丢掉也能通过第 1 条"）

| 场景 | 她身上 | 接缝带均值 | 接缝带覆盖 | 判定 |
|---|---|---|---|---|
| 蹲姿·地面 | 0.09（前 3.66） | 75.95 | 99.6% | PASS |
| 坐长椅 | 0.23（前 13.73） | 37.44 | 97.7% | PASS |
| 坐桌沿 | 0.20（前 24.07） | 46.62 | 96.8% | PASS |

全姿态回归（5 个地面/座面动作 + 3 个物件场景）全部正常，耗时 4.1~7.4 秒不变。

### 六、还没解决的：场景内路线没改

`shoulder` / `peek` / `hem_peek` 走的是 `run()` 的场景内分支，
那里的角色是**模型直接画进图里的**，没有 alpha，`shadow_under` 用不了。

而且这条路上"阴影落在人身上"未必是错的：她扒在肩膀上时，**人就是承接面**，
AO 压在毛衣上是对的，只是不该也压在她身上。

要修得用 `character_mask` 近似 alpha。没做，因为：
- 那个掩码是启发式的（蓝色主导 ∩ 差分），她的白围裙白鞋不在里面。
  拿它当 alpha → 蓝的部分不压暗、白的部分压暗 → 会在她身上出现色块接缝，
  比现在"整体压暗"更难看。
- 回灌测量也没打通：`run()` 里 `placed` 的坐标框和 `character_mask` 的坐标系对不上，
  交集为空，量不出"有多少压在她身上"。

先记着。等 `change_mask` 能给出可信轮廓（或者有别的 alpha 来源）再动。

## 十九、合并两次 VLM，以及一次被 profile 推翻的估算

### 一、合并本身

物件路线原来调两次 VLM：`vlm_profile`（景别/人物框/腿框/光向）+ `vlm_props`（座面框）。
第二次就为了问一句"哪个能坐"，代价 1.6~3.8 秒。

现在座面框并进画像，`PhotoProfile` 多一个 `props` 字段。
人物路线本来就只有一次调用，不受影响；物件路线从 5.2~7.4 秒降到 2.4~3.5 秒。

同时把 `vlm_props` 里那套容错解析抽成 `_parse_props` / `_props_from_text`，
两个入口共用——否则"同一次分析"会在两条路上给出不同答案。

### 二、合并的真实风险是"原有字段被带坏"

往 prompt 里加问题，模型可能在**已有字段**上开始出错，而且退化是静默的。
所以先按老的两段式抓基线（`experiments/step14_vlm_merge.py --base`），
逐字段比对。8 张场景，只跑一次的结果：

| 项 | 结果 |
|---|---|
| `framing` / `light` | 全部一致 |
| `person` / `legs` 框 | 一处 3.5% 偏移（模型抖动） |
| `props` 数量 | 3 处：2→1（被丢的那条本来 `usable=False`）、0→1、3→2 |
| **`餐桌` 座面前沿** | **`y 395 → 0`，直接判成不可用** |

最后一条是真退化：模型把"桌面朝上的那一大块"整个框进来（`seat=[0,0,999,485]`），
正是老 `PROP_SYS` 专门警告过的失败模式。合并后那段警告被稀释了。

两处修：
1. `PROFILE_SYS` 里补一条针对桌面的反例（"不要把它整个框进来，那会得到
   y1≈0、x1=0、x2=999"），`_user_text` 也点明"要的是竖立面前沿，不是朝上的水平面"。
   改完餐桌回到 395，与基线一致。
2. 加一层兜底 `_props_or_retry`：**合并结果确实不可用**时才补问一次。
   正常路径仍然单次；最坏情况退回老的两段式，不会更差。

### 三、`selfie` 那次"退化"其实是抖动

基线里 `公园自拍` 的 `selfie=True`，合并后 `False`，看着像被带坏了。
同一张图、同一 prompt 连跑三次：`False / True / True`——**这是模型的逐次抖动**，
`temperature=0.0` 也压不住。

而 `selfie` 只影响候选**排序**（`filter_by_framing` 里 `pref + rest`），
不排除任何动作，所以属于软影响。`has_prop` 同理（管道已经不看它了）。

**方法论**：单次 A/B 分不清"退化"和"抖动"。要么重复三次，要么把判据落在
"影响不影响到输出"而不是"字段值相不相等"。

### 四、顺带发现的真问题：CPU 根本不是 0.25 秒

合并之后我想确认"还剩多少"，于是把 VLM 换成缓存，只跑 CPU——**1.8~3.5 秒**。

这跟我一小时前写进 `docs/12` 的判断（"95% 在等 VLM"）直接矛盾。
`cProfile` 一跑就清楚：

| 函数 | 耗时 | 占 CPU |
|---|---|---|
| `match_ambient` | 2.23s | 59% |
| `_qc_scores` | 1.00s | 26% |
| 其余全部（重打光/阴影/接触核/合成/存盘） | 0.55s | 15% |

**两个最慢的都跟画质无关**：

- `match_ambient` 求的只是一个**三元色偏向量**（她身上均值 − 她外圈均值），
  却在 1280×1600 全分辨率上跑 `MinFilter(5)` / `MaxFilter(17)` / `MaxFilter(5)`，
  光 `rankfilter` 就 2.86 秒。改成缩到 320 宽再算，位移量照样正确；
  应用时按 alpha 羽化铺回全图，顺手消掉了原来 `core` 硬边造成的接缝。
- `_qc_scores` 的注释原文就是"只做记录，不做拦截"，是纯诊断量，
  同样在全分辨率上跑两个 `MaxFilter(7)/MinFilter(7)`。改到 400 宽。

结果：

| | 改前 | 改后 |
|---|---|---|
| `match_ambient`（长椅/客厅） | 871ms / 2120ms | **94ms / 165ms** |
| CPU 全链 | 1.8~3.5s | **0.55~0.76s** |
| 单张端到端 | 4.1~7.4s | **2.4~4.3s** |

输出验证（`experiments/step15_cpu_budget.py`）：四张场景的成品平均亮度差
0.002~0.015 灰阶——看不出来。

### 五、这次估算错在哪儿

我是按"重打光 57ms + 色温 34ms + 侧光 10ms + 阴影 20ms"加出来的 0.25 秒。
错在两点：
1. **只算了我改过的函数**，`match_ambient` 和 `_qc_scores` 是早就存在的，
   因为"没在改它"就没去量；
2. `match_ambient` 内部比我以为的慢一个量级——全分辨率形态学滤波的开销
   凭直觉估不出来。

**结论**：凡是要判断"哪一段最慢"，先 `cProfile`，别用分段计时相加。
分段计时只回答"我量的那几段各多久"，不回答"总时间去哪了"。

## 二十、多角色：角色从代码里抽出来，以及等身带来的两个硬约束

### 一、抽出来的原因

在这之前，角色是**写死在代码里的**三处：`_encode_refs()` 固定读 `05_chibi_front/side.png`，
`build_sprite_prompt()` 固定写"Q 版 2 到 2.5 头身"，
立绘缓存固定 `assets/sprites/`。加第二个角色必须改这三处，而且两套同名立绘会互相覆盖。

`s3/characters.py` 用一个 dataclass 收敛：

| 字段 | 错了会怎样 |
|---|---|
| `refs` | 换脸、换衣服 |
| `identity` | 同上 |
| `body` | Q 版和成人比例串味 |
| `scale` | 大小全错 |
| `sprite_dir` | 两个角色的立绘互相覆盖 |

`scale` 是**相对人物身高**：`chibi` 0.26（≈45cm 手办）、`dafeiyu_mature` 0.92（≈160cm 等身）。

同时把"尺度由谁决定"拆开了：原来 `Action.scale_ratio` 混着角色和动作两件事，
现在立绘路线取 `character.scale`，`Action.scale_ratio` 只给场景内路线兜底。

### 二、从设定图到一个可用立绘，实测可行

用户给的是**三视图 + 细节图**的拼版（1448×1086）。处理链路：

1. 按墨迹投影找空白谷，切成 front / side / back / 细节栏（谷底在 x≈380 / 690 / 1030）；
2. 从细节栏裁出脸部特写；
3. 参考图取 **front + side + face**（细节栏那 4 张拼版当参考太杂，去掉）；
4. `build_sprite_prompt` + 这 3 张参考图 → Seedream 生成 → `key_white` + `trim`。

结果：**12 秒、0.12 元，内部空隙 1.14%**，和设定图高度一致
（发色、围裙鲸鱼刺绣、尾巴、鞋子全对上），**7 头身比例也守住了**——
说明 `body` 字段确实在起作用；这里如果把 Q 版那句"2 到 2.5 头身"留在提示词里，
模型会给她画成大头娃娃。

### 三、等身的第一个硬约束：竖构自拍放不下

`_sprite_placement` 原来按"贴着她腿边 6px"算横向位置。等身角色宽度是玩偶的 3.5 倍：

| 场景 | 等身需要 | 实际给到 | fit_k |
|---|---|---|---|
| s01_mirror | 1477px | 385px | 0.26 |
| s02_park | 1203px | 863px | 0.72 |
| s03_sofa | 1461px | 313px | 0.21 |
| s04_full | 1355px | 541px | 0.40 |
| s05_walk | 1462px | 489px | 0.33 |

原因是构图：竖幅 1280 宽，人本身占约 450px，两侧各剩约 400px；等身角色要 700px。
**5/5 全部放不下。**

处置：按可用宽度反算 `fit_k` 自动缩小（下限 0.5），结果里带 `fit_k` / `space_limited`
供前端提示。没有选择"允许重叠"——重叠要在人身上投出她的影子才不假，而我们现在做不到
（见 §十九 的 `shadow_under`：只处理地面/座面，不处理"投影到另一个人身上"）。

### 四、等身的第二个硬约束：必须看得见脚

`person_h_px` 是**人物框的高度**。半身照里那只是画面里看得到的那半截
（s02_park 1308px，实际人高得多）。拿它乘 0.92 会把她画得跟半身人一样高，
脚底线也错（画面底边不等于地面）。

玩偶尺度差一半还能看（45cm → 25cm），等身差一半就完全不是等身。
所以：`scale ≥ 0.6` 且 `framing != "full"` → 直接拒绝，不猜系数。

### 五、等身不适用于物件路线

物件路线的尺度是 `SEAT_H_FRAC`（占画面高 12~42%）+ `SEAT_H_RANGE` 夹取，全按玩偶标的。
更要紧的是没人物的照片里**没有可靠尺寸参照**，家具的远近大小只能靠经验比例猜，
猜出来的"等身"不是等身。所以直接拒绝，并指向"改用手办尺度角色"。

### 六、防呆

- 非默认角色 + 场景内动作（shoulder/peek/hem_peek）→ 拒绝。
  那条路是模型把角色画进照片，换角色等于换提示词，现在只有 Q 版那套；
  不拦的话会静默拿 Q 版提示词去画新角色，出来四不像。
- 未知角色 id → 退到默认角色，不抛异常。id 从 API 参数一路传进来，拼错不该让整张图失败。

### 七、还没做的

1. **遮挡**。等身最缺这个：她永远画在最前面，压到人身上时没有影子也没有遮挡。
   要做得对，需要前景 mask + 把她的影子投到人身上。
2. **等身的动作文案**。现在直接复用 Q 版的动作 `desc`，有些词是体型专属的
   （"短腿垂在肩膀前面"、"圆圆的小团子"）。`Action.desc_by_body` 已经在注册表里留了位置，还没填。
3. **等身的舞台**。等身真正能发挥的是**横构图 / 远景 / 人在一侧**的照片，
   自拍几乎都用不了。这不是实现问题，是产品定位问题。

## 二十一、遮挡：把"她被人挡住"做进立绘路线

### 一、先撤回一个错误结论

§二十 里我写过"等身角色在竖构自拍里放不下（5/5 场景要缩到 21%~72%）"。
**这个结论是错的**——它的前提是"她必须完整可见"。

用户直接指出了问题："这张图明明就可以把鲸鱼娘放在人物身后，探出一半的身体。"

对。完整可见时她需要约 700px 横向空地；**被挡住一半时，她只需要一条能露出来的缝**。
前提一换，那 5 个数字全部失效。这是典型的"把实现约束当成客观事实"。

### 二、机制

三块拼起来：

1. **人物掩码**（`s3/seg.py::person_alpha`）：MODNet ONNX，512 短边推理，0.17s。
2. **收边**（`s3ops.silhouette_edge`）：在某个纵向带里取前景的左右轮廓，
   逐行取中位数——不是用人物框。框的左沿通常在她手臂外侧，而那一段轮廓其实凹进去。
3. **合成**（`s3ops.occlude`）：`out = result·(1-fg) + base·fg`。
   **放在最后一步**：她的接触阴影不该压到前面的人身上，
   而重打光只作用在她自己的 alpha 内（被挡住的部分白算，可忽略）。

数学上等价于"把她贴在人物图层下面"，但不需要真的重排合成顺序。

### 三、为什么不用 GrabCut

先试的 `cv2.grabCut`（带人物框先验）。在**两人重叠、都穿深色外套**的照片上直接失效：
她深色外套整块被判成背景（于是鲸鱼娘会画到外套上面），同时糊到了旁边男生的额头。

不是"参数没调好"——它没有语义，分不清"两块深色的布"和"两个人"。
MODNet 一次就对：两个人的脸、头发、外套都干净，背景和长椅排除在外。

**模型来源**：GitHub releases 在这个环境不通（`curl` 返回 HTTP 000），
hf-mirror 通。`Xenova/modnet/onnx/model.onnx`，25.9MB。

### 四、装进 MODNet 之后才发现的第二个问题

MODNet 是**显著目标**模型，不是人像专用的。`s02_park`（两人坐长椅）里，
画面下半部的**长椅和背景**也被判成前景——y>700 之后掩码左右边界直接是 0 和 1279，
整幅宽都算"人"。

后果不是"轮廓不准"，是灾难性的：遮挡阶段拿这张掩码把成品盖回去，
**她整片被擦掉**，成品里只剩几条蓝边。

两层补救：
1. `_keep_person_components`：只保留"穿过人物框内缩 40% 中心区"的连通域。
2. 半身构图的取边带限制在**人物头到肩**那一带（再往下掩码不可靠）。

### 五、露出多少不该是常量

`s02_park` 实测：两个人的头只占 x 204~1091，左边只剩 172px；
而她按 0.55 露出需要 526px。写死比例的结果是她被推出画面。

改成**按剩余空间反算**：`vis = max(0.16, min(want, room / target_w))`。
这种构图本来就是"从人缝里探出一点点"，露 18%~30% 才是对的样子。

### 六、当前状态

| 场景 | 结果 |
|---|---|
| 全身照 · 等身 · behind_peek | **可用**（实测 s04_full，见 `output/behind_peek_e2e.jpg`） |
| 半身照 · 等身 · behind_peek | **明确拒绝**，见下 |
| 全身照 · 手办尺度 · behind_peek | 可用（383px，与 leg_hands_behind 同尺度） |
| 其他动作 / 角色组合 | 回归通过，未受影响 |

半身照为什么还不支持：`s02_park` 里长椅和两个人**连成一个连通域**，
连通域过滤按"是否穿过人物框中心区"分不开它们，遮挡会误伤。
这是掩码质量的问题，不是调参数能解决的。要支持得换更干净的人物掩码
（按人实例分割），或者改成"肩线锚点 + 只遮挡头部那一小块"。

### 七、顺带修掉的一处

`target_w = target_h * 0.78` 是写死的 Q 版宽高比。成人形态的立绘是 706×1527 ≈ 0.46，
按 0.78 算她的宽度会高估 70%——直接影响"横向让位"和"被挡住多少"。
改成取立绘真实宽高比之后，`s04_full` 上 `leg_hands_behind` 的自动缩放
从 0.5（撞下限）回到 0.56，她不再被白白压小。

### 三、抓到的四个问题（两个已修）

**1. 尺度尺子退化（已修）**

e03 桌沿 34.5%、e05 台阶 39.0%，而 e01/e02/e04 都在 20~22%。根因：

```python
if span > 0.6:      # 用"座面宽度"兜
    target_h = max(by_frame, seat_w * SEAT_W_RATIO[kind])
```

`span≈1.0` 时座面横跨整个画面，`seat_w` **就等于画面宽度**——它量的不是
"家具多大"，而是"画面被家具占满了"。这把尺子在这个区间没有信息。
改成 `0.6 < span < 0.9`：超过 0.9 判"被画面裁掉，宽度信息不可用"，退回画面比例。
修后 e03→19.9%、e05→15.9%，十张全部落在 14~24%。

**2. `run_sprite` 不拦场景路线的动作（已修）**

自动匹配会挑到 `peek` / `shoulder` / `hem_peek`，而 `run_sprite` 没检查 `render`
就跑了，后果有两个：
- 落点是通用的"站腿边"，出来是她站在地上，跟"扒肩探头"毫无关系；
- **静默花 0.12 元生成了一张这个动作的立绘**（实测误生成 `peek__` 和 `shoulder__`
  两张，0.24 元）。

已在入口挡住并给出可操作提示。

**3. 半身照在立绘路线里没有可用动作（产品空白，未修）**

所有地面动作都要求 `framing == "full"`。半身照（p02 室内沙发、p04 咖啡馆）过滤后
候选集为空，最后落到物件路线去坐沙发扶手 / 坐桌沿。这不是 bug，是动作库缺一类
"只和人上半身交互"的立绘动作（原本那类是场景路线的 `shoulder` / `peek`）。

**4. 座面横向定位不稳（未修）**

`p05` 人坐在长椅上，但 VLM 给的长椅框 + `x1 + width*0.32` 这个锚点把她放到了
椅子**前面**的地上（运动鞋旁边）。她坐在半空，脚下是路面。
这是"座面横向范围不稳定"的老问题——同一件家具，框多长算一段坐垫没有客观边界。

### 四、观感结论

放大接缝看（`output/step16/seam_zoom.jpg`）：

- **沙发 / 长椅 / 扶手椅三张坐对了**：臀落在座面，腿垂在座沿外，接触线正好在髋部；
- **桌沿**：她坐在桌面前沿，接触线对，但"坐在桌沿上腿悬空"这个姿态本身
  在物理上需要桌子有厚度，画面里能看到桌面前立面，成立；
- **台阶**：坐在台阶边缘，成立；
- **p05**：坐到了椅子前面的地上，不成立（问题 4）。

### 五、两条方法论

1. **同一张图、同一 prompt，VLM 会抖**：p02 第一次 `person=None`（画面里明明有人），
   第二次是 person；p01 两次自动匹配给出不同动作（`leg_hands_behind` / `crouch_by_leg`）。
   所以"自动匹配好不好"这个问题，单次结果不能下结论。
2. **测主路径时要把候选集收窄**。第一版直接用 `pick_action_v2`，
   它挑的场景路线动作会把 `run_sprite` 带到一个未验证的分支上——
   测出来的不是"主路径的表现"，而是"两个子系统拼错之后的表现"。

## 二十三、规划优先的生成路线：VLM 先出分镜，再让生图模型画

### 一、用户的提议与它的价值

> "每张图的生成首先由视觉模型判断鲸鱼娘该在什么位置，做什么动作，再调用生图大模型，
> 而不是把单一的动作贴在原图上。"

这个方向正对立绘路线的两个硬伤：

| 立绘路线的硬伤 | 生成路线怎么解决 |
|---|---|
| 动作是**枚举**的（9 个），半身照直接没有候选 | 动作针对这张照片现编 |
| 她**永远贴在最前面**：手不会真的搭在人身上，也不会被挡住 | 遮挡与接触由同一次扩散完成 |

### 二、规划器：`s3/plan.py`

一次 VLM 调用产出分镜：`where`（位置）/ `action`（动作）/ `region`（她的外接框）/
`region_name`（依托物）/ `anchor_kind` / `reason`。

在 10 张新场景上实测，**位置与动作的判断质量很好**：

- 每一张都找到了具体的依托物（长椅座面 / 石阶踏面 / 桌沿 / 扶手椅坐垫 / 人物右脚旁边的地面）；
- 动作都写成可执行的句子，例如"坐在石阶踏面上，双腿自然垂在台阶边缘，双手环抱着膝盖，
  抬头望向石阶上方的林荫方向"；
- **主动避开了手部抓握**（10 张里 8 张写的是"抱膝""双手背在身后""双手交叠"）——
  这条是有意写进 prompt 的，因为本项目的实测结论是手部抓握画不好。

但它的**尺度估计系统性不准**：p01 给 7.5%（该 16%）、p03 给 9%（该 14%）、
p05 给 35.5%（该 24%）。它擅长"在哪、和什么发生关系"，不擅长把"40 厘米"换算成
画面百分比——后者需要画幅、人物身高、透视，而这些我们手上有精确值。

所以分工改成：**位置和动作听规划器的，大小听程序的**。

### 三、三种做法，只有第三种成立

| 做法 | 位置/动作 | 尺寸 | 遮挡互动 |
|---|---|---|---|
| A 纯规划 → 生成 | 好 | **不可控：实测 1.7~2.8 倍** | 自然 |
| B 规划 + 尺度锚点 | 好 | 仍不可控（p05 反而 39.8% → 53.1%） | 自然 |
| C **布局引导生成** | 好 | **精确** | 自然 |

**A/B 为什么救不回来**：`build_companion_prompt` 里的位置框是**画面百分比约束**，
而 `s2_prompt.py` 里早就躺着一条 `_DEPRECATED_PERCENT_SCALE = "（已证伪）角色高度约占
画面高度的 N%"`——这类指令模型不服从，之前 A/B 就证过。我又试了**物体相对锚点**
（"头顶只到人物膝盖，整个人不超过小腿的一半高"），仍然不服从。

**结论：这个生成模型对"把角色画小"没有可控性。** 这正是当初从场景路线转向立绘的原因，
绕了一圈又撞上同一堵墙。

### 四、C 的做法（已实测成立）

1. 用现有的 `_sprite_placement` 把立绘按**精确尺寸**贴到照片上——位置和大小都由程序算，
   这一步和立绘路线完全一样；
2. 把这"带小人的照片"当图1 送给模型，并要求：
   - 她的**外接框位置和大小必须和贴上去的一模一样**；
   - 除她和她身下的接触阴影外，**其他一律不许改动**。
3. 出图。

实测 `p05_bench_sit`（目标 241px = 画面高 23.5%）：

- 出来的人物**就是那个尺寸**，头顶在人物大腿位置；
- **男士的腿真的挡在她前面**——真遮挡，由扩散过程生出来，立绘路线做不到；
- 背景、人物、树、光线全部没动。

**为什么百分比不行而"图里已有的框"行**：参照物从抽象变成了具体。
模型不需要"理解 20% 是多高"，它只需要"照着这个小人重画一遍"。

### 五、还没做的

1. `run_guided()` 还没进管线。现在的实现是 `experiments/step17_planned_generate.py`
   里的 `--guided`，配方已验证但没接到 API / 前端。
2. **引导图里的立绘是"照抄"的起点**：如果立绘姿态和规划的动作不一致
   （比如立绘是坐、规划的是蹲），模型会被两个信号拉扯。需要让规划器**只在
   已缓存的立绘动作里选**，或者按规划去生成对应立绘（0.12 元/姿态，一次性）。
3. 成本模型变了：每条 0.12 元 + 10 秒。立绘路线是 0 元。
   所以这条应该是**"精细模式"**，而不是默认路径——日常出图仍走立绘。

## 二十四、动作匹配与 60cm：一次对上一节的纠错

### 一、用户报的两件事

> "这张图不太好，动作不匹配，我希望对鲸鱼娘尺寸有个明确的规定，60cm 高，写进提示词。"

贴着 `guided_out2.jpg` 看，两件事都成立：

1. **动作不匹配**：规划器说的是"坐在长椅座面上"，贴上去的立绘却是**站姿**
   （`leg_hands_behind`），成品成了脚悬在长椅前沿外面的半空站姿。
2. **尺寸没有硬规定**：`PLAN_SYS` 里写的是"真实身高约 40 厘米"，角色注册表里
   `scale = 0.26`（≈45cm），提示词里一句话都没提厘米数。

### 二、动作不匹配的根因不是规划器判断错

是**两个信号打架**：

- 引导图是一张**已经画好的立绘**（只能贴已缓存的那 10 张）；
- 提示词里的姿态是规划器**自由创作**的一句话。

模型同时收到"照这张小人的姿势重画"和"按文字改成另一个姿势"，各听一半。

§二十三 第五节把这条列为"还没做的"，现在的修法是它当时提的方向之一：
**让规划器只在已缓存的立绘里选**。

`s3/plan.py` 加了 `options` 参数，把候选清单（id + 名称 + 姿态描述 + 依托类型）
写进系统提示词，要求模型输出 `action_id`；`app/pipeline.py` 的
`available_sprite_options()` 扫描立绘缓存目录生成这份清单。

这样**姿态的定义权归立绘**（那才是模型要照着重画的），规划器负责的是
"依托物叫什么"——它把 `{anchor}` 换成画面里真实的那件东西（"长椅的木条座面"），
再补一句她朝哪看。

实测 6 个场景，`action_source` 全部是 `plan`，而且挑得各不相同：

| 场景 | 选中动作 | 依托 |
|---|---|---|
| P05 长椅·坐着的人 | `leg_hug_knee` | 人物右脚边的地面 |
| P03 街道·走路的人 | `leg_hands_behind` | 女士左小腿外侧的地面 |
| P01 逆光全身 | `leg_hands_behind` | 女士左小腿外侧 |
| E04 扶手椅 | `seat_edge_sit` | 扶手椅的布艺座垫 |
| E05 台阶 | `seat_edge_sit` | 最下方石阶的踏面 |
| P04 咖啡桌 | `seat_edge_sit` | 桌面边缘 |

**残留问题：规划器有抖动**。同一张 p05 连问三次，分别给出
`seat_edge_sit` / `leg_hands_behind` / `leg_hug_knee`——三个都说得通
（他坐着，长椅座面、他脚边的地、他两脚之间的地都成立），所以不算错，
但同一张照片每次结果不同，产品体验上是不稳定的。
`temperature` 已经是 0.2，要进一步收敛得给"优先级规则"（比如"有座面优先坐座面"）。

### 三、60cm 落到三个地方

| 位置 | 之前 | 现在 |
|---|---|---|
| `s3/characters.py` | `scale=0.26`（≈45cm，拍脑袋） | `height_cm=60.0`，`scale=60/175` |
| `s3/plan.py::PLAN_SYS` | "真实身高约 40 厘米" | "**真实身高 60 厘米**，站在 175cm 的成年人旁边，头顶大约刚过对方的膝盖" |
| `s3/s2_prompt.py` / `GUIDED_PROMPT` | 没有厘米数 | "她真实身高 60 厘米，不要画成与人物同高的成年人" |

`REF_PERSON_CM = 175.0` 是唯一的假设：照片里量不出绝对厘米数，只能
"60cm 对 175cm 的人 = 0.343 个人高"。儿童照片会偏，但改身高只需改一个数。

### 四、这里要纠错：§二十三 说"布局引导 → 尺寸精确"，是错的

§二十三 第五节写的是实测 `p05_bench_sit` "出来的人物**就是那个尺寸**"。
那一次是**目测**的。这一轮做了客观测量，结论反过来了。

测量方法（`s3/measure.py`）：生成提示词里有一条硬约束"除她和接触阴影外其他
一律不许改动"，所以把成品和原照片逐像素相减，差异集中的那一块就是她。
两个必须做的细节——**只在规划框附近找**（否则模型顺手改的背景光线会污染，
实测 e05 从 42% 被撑到 73%）、**取主连通域而不是全 mask 的 bbox**。

客观测出来的六张：

| 场景 | 人物占画面 | 60cm 应占 | 实测 | 倍率 |
|---|---|---|---|---|
| P05 长椅·坐着的人 | 90.6% | 31.1% | 35.2% | 1.13× |
| P01 逆光全身 | 62% | 21.3% | 31.8% | 1.49× |
| P04 咖啡桌 | 74% | 25.2% | 41.1% | 1.63× |
| P03 街道·走路的人 | 55% | 18.7% | 30.7% | 1.64× |
| E05 台阶 | 无人物 | 26.4% | 42.2% | 1.60× |
| E04 扶手椅 | 无人物 | 26.4% | 44.8% | 1.70× |

**没有一张达到 60cm**，全部偏大 1.13~1.70 倍，中位 1.60 倍。

顺带修了测量工具本身的一处偏差：一开始用高阈值（diff>80）取"只有她本体"，
理由是"阴影 diff 小，高阈值能排除掉"。实测反了——她的浅色部分（白围裙、白袜、
浅蓝发梢）diff 也只有 40~60，高阈值框不到，bbox 只剩深色裙子那一块
（p05 报 24.2%，而同图低阈值是 35.2%，差 1.45 倍）。
**测量工具本身在系统性低估**，这个如果不查出来，后面的判断全是错的。
低阈值偏高估（把脚下的接触阴影算进来，约 +5~10%），但那个方向安全得多。

### 五、三条控制手段，全部失败

以为是"提示词写得不够硬"，逐条试了：

| 手段 | 结果 |
|---|---|
| ① 提示词"外接框位置和大小必须一模一样，不许放大"，并把"框"明确定义成"从头顶呆毛尖到鞋底、从尾巴末端到头发最外侧" | 无效：1.51× → **1.49×** |
| ② 提示词补一句可对照的实物参照（`_size_anchor`："头顶刚过人物膝盖，不超过大腿高度"） | 无效：pos 里加了这条，倍率不变 |
| ③ 引导图里把她**缩小**：21.3% → 14.2% → 10.6% | **模型完全无视**，成品稳定 31~34% |
| ④ 引导图换成**纯色剪影**（品红，立绘 alpha），要求"填满这个形状、边缘与剪影重合、品红必须完全消失" | 无效：p01 32.3%（贴立绘时 31.8%），形状约束也没用 |

④ 的对照也做了：把引导图里的小人**放大**到 42.8%，成品跟到 64.1%（3.0×）。
所以这个模型不是"忽略引导图"，是**只在大尺寸时按比例跟，小尺寸时按自己的先验重画**。

一句话：**它对"卡通小人"有一个内在的尺寸先验，压过提示词、压过引导图尺寸、压过剪影形状。**

### 六、这个先验是一条下限，约 26%~30% 画面高

六张的实测值是 30.7 / 31.8 / 35.2 / 41.1 / 42.2 / 44.8——**没有一张低于 30%**，
而它们的目标是 18.7~31.1。也就是说目标只要低于这个线，就必然被顶上去。
唯一接近达标的是 P05（目标 31.1% 已经贴着线，实测 35.2%，1.13 倍）。

换算成实用判据：她 60cm，人物 175cm，所以 **60cm 占画面高 = 人物占比 × 0.343**。
要让它 ≥ 30%，人物得占画面高 **87.5% 以上**（几乎贴满画幅的全身照）。
绝大多数真实照片达不到，所以**"60cm"在这条生成路线上基本画不出来**。

已写进代码：`app/pipeline.py::GUIDED_SIZE_FLOOR = 0.30`，`run_guided` 在
`target_pct` 低于它时给 `size_limited=True` 并返回一句人话告警，
说明"会偏大几倍、要精确请改用立绘路线"。

同时**每次都实测并返回** `measured_pct` / `size_err`——尺寸控制不住，
至少要让它变成一个可观测的量，而不是让用户拿眼睛猜。

### 七、mask 局部重绘：接口不支持

最彻底的办法是给一个 mask 只重绘她所在的区域，那样尺寸和位置都由 mask 定死。
实测往 `/images/generations` 传 `mask` 字段：

- 返回 **200**，不报错；
- 但**效果上被静默忽略**：一张图里放两个深色矩形、mask 只框左边那个，
  提示词"把深色矩形换成蓝色小猫"，结果**两个都被换成了猫**。

所以 `mask` / `mask_image` / `masking` 三个字段名都不用再试了。

### 八、两条路线现在怎么分工

| | 立绘路线 `run_sprite` | 引导生成 `run_guided` |
|---|---|---|
| 尺寸 | **100% 精确**（程序 resize 到 `target_h`） | 偏大 1.2~1.6 倍，且不可控 |
| 动作 | 枚举的 10 个 | 从这 10 个里选（规划器挑） |
| 遮挡互动 | 无（除 `behind` 类动作） | 自然，真正被人挡住 |
| 成本/耗时 | 0 元 / 3~5 秒 | 0.12 元 / 8~12 秒 |

**结论：60cm 这个规定在立绘路线上是无条件满足的，在生成路线上做不到。**
要"精确 60cm"就走立绘；要"真正被人挡住、勾肩搭背"就走生成，接受偏大。

### 九、还没做的

1. **`run_guided` 没接进 API / 前端**。现在只有 `experiments/step19_guided_e2e.py` 能跑。
2. **规划器抖动**（同一张图三次三个动作）没收敛。
3. **物件路线的尺寸没有厘米依据**：`size_basis=percent_estimate`。
   没人物的照片里量不出家具真实尺寸，也就烧不出 cm/px。要真做，得用
   "座面高 ≈ 45cm，从座面到地面的像素数 = 45cm"这条物理关系，但 `floor_y`
   在无人场景里经常给不准。
4. **接触阴影要靠生成模型画**，它经常画得很淡（E04 扶手椅几乎没有）。
   立绘路线是程序化画阴影，这条明显更可控。
5. **方差大，且不能靠"多生成几张取最优"**：p01 上试了 7 次，全部落在 31~45%，
   一次都没接近 21.3%——它根本不是随机误差，是下限。同样的目标 21.3%，
   贴立绘引导和贴剪影引导分别给出 31.8% 和 32.8%，几乎一样。

## 二十五、简易 2.5D 场景：让她别坐到咖啡杯里

### 一、用户报的两个新问题

> "在最初对图片进行解析的时候我希望会同时解析出图片里的物品信息，建立简易的 3D 场景，
> 再考虑鲸鱼娘的位置，避免出现 p04 这种和咖啡杯重叠，p05 抱腿坐的姿势腿过长了。"

两个问题的根子完全不同：

| 问题 | 根子在哪 |
|---|---|
| p04 她坐在咖啡杯上 | **程序不知道那个位置有东西**。落点只用一个 `center_x`，从规划器的框中心算出来，从来没有"这里有什么"这个概念 |
| p05 抱膝的腿太长 | **立绘本身就画错了**。跟生成路线无关，那张 png 上的小腿就是从膝盖往下伸直到底的 |

### 二、p04：为什么"解析出物品"就能解决

原来的落点链路是：

```
规划器给框  →  中心 x  →  直接贴
```

规划器说的是"坐在桌面边缘"，这在语义上没错。但桌面正中摆着一杯咖啡，
而"中心 x"这个数**不带任何关于那里有什么的信息**。它当然就坐到杯子上去了。

补上物品信息之后，链路多了一层：

```
规划器给框  →  中心 x  →  查场景图有没有东西  →  有就横向挪
```

### 三、为什么是 2.5D 而不是真 3D

单目照片做不出真三维。要一个"够用"的东西，只要回答三个问题：
**它占哪块地方 / 它离我多远 / 它能不能坐**。

| 维 | 从哪来 | 回答什么 |
|---|---|---|
| 横向 x | 外接框 | 横向会不会撞 |
| 纵向 y | 外接框 | 竖向会不会压 |
| **深度 z** | **接地线 `base_y`** | 谁在前谁在后 |

`base_y` 是"这件东西和它下面那个面接触的那条线"。它是单目照片里
**唯一可靠的深度线索**——脚在地上、离镜头越近，那条线在画面里越靠下。
桌上的杯子同理：它在桌面上越靠前，杯底那条线越靠下。

**没有走单目深度估计（MiDaS / DepthAnything）**，理由是它给的是稠密但
**不带语义**的相对深度：既分不开"杯子"和"杯子后面的墙"，也回答不了
"这个面能不能坐"。模型体积和推理耗时还会翻倍。
VLM 给一个框 + 一条接地线，信息量小得多，但每一条都直接可用。

### 四、物品从同一次解析里来

用户的用词是"**同时**解析出物品信息"，所以没有加第二次 VLM 调用。
`PROFILE_SYS` 新增 `objects` 字段，和人物框、光向、可坐物件一起出：

```json
{"kind": "cup", "box": [306, 787, 608, 947], "base_y": 947,
 "support": "table", "solid": true}
```

`objects` 和 **`props` 是两个字段，不是一个**：

- `props` 回答"能不能坐"（沙发/长椅/椅子/床/桌/台面/台阶），带 `seat` 框；
- `objects` 回答"占了哪块地方"（还包含杯子、盘子、书、手机、花盆、人）。

把它们混成一个字段会让两个判断互相稀释——为了报"杯子"，VLM 会更少报"沙发"。
`max_tokens` 从 520 提到 980，因为截断的后果不是"少几个字段"而是整段 JSON 坏掉，
坏掉之后 `objects` 解析不出来，避让就**静默失效**了。

### 五、三条判定规则

1. **谁更近**：`base_y` 大的离镜头近。
2. **能不能重叠**：她的脚线比某物体的接地线低（她站在它前面），重叠合法——
   她挡住它是自然的前后关系；反之她站在它后面，而**生成路线画不出"物体挡她"**，
   只会画成她穿过去，所以直接判冲突。
3. **坐在谁身上**：落点在某可坐物的 `sit_y` 附近且横向在它范围内 → 只允许和它自己重叠。

#### 一个反直觉的例子

p04 里她坐在桌面前沿（脚线 ≈855），咖啡杯的接地线是 947，**比她还靠下**。
按"更近就合法"的直觉该放过，但那是错的：杯子放在桌面上，她的脚也在桌面上，
**两者是同一层**，她会坐进杯子里。

所以判据不能只看"谁更近"，得看**"她的落脚面和它的落脚面是不是同一个"**。
这就是 `sit_target` 和 `tol = 目标身高 × 0.15` 存在的意义。

#### person 不算障碍

她挡住人物下半身是正常的，不是穿模。把 `person` 当障碍会把她从人身边赶走，
毁掉整个构图——而这条流水线的目的就是让她和人物互动。

### 六、遇到的两个数据问题

**1. `sit_y` 的兜底不能取框的上沿。**
VLM 漏给 `sit_y` 时，第一版用了 `y1`。实测 p05 的长椅
`box=[272,375,999,690]`，算出来 `sit_y=375`——那是**靠背顶**，而照片里座面在
y≈560。差 185 个归一化单位，后果是"她坐在靠背上"，比不坐还离谱。

改成 `y1 + 0.60 × (y2 − y1)`：地面到座面大约占整件家具高度的 55~65%
（沙发偏矮、餐椅偏高、长椅居中），取 0.60。这是**近似值**，
所以 `sit_target` 的匹配容差要按她的身高给足，不能当精确值用。

**2. 深度序号排反了。**
`base_y` 越大越近，但第一版直接从小到大编号，于是 `depth=0` 给了**最远的**
背景桌子，红色（"最近"）也给了它。排序倒过来之后才对。

### 七、可视化：`s3/scene3d.py::render_scene_overlay`

把场景叠回照片：每个物体一个框、一条接地线、可坐面画白虚线、左上角标深度序号。
颜色按深度从红到紫。

这张图不是装饰。**出问题时第一眼看它**：如果避让后的位置在这张图上就压着杯子，
那是解析错了（框歪了/杯子漏了），跟生成模型无关。没有这张图，
"简易 3D 场景"只是一句说了不算的话。

### 八、p05：抱膝立绘的腿为什么那么长

诊断结论：**立绘本身错了，跟生成路线无关**。

旧 `desc`："双腿紧紧蜷起来收成一团、小腿完全折在大腿下面看不见"。
出来的图是**膝盖在中间、小腿从膝盖往下延伸到底、脚离屁股很远**——读作"坐着伸腿"。

复盘：旧文案三句都在描述**姿态关系**（蜷起来、折在下面），
**没有一句描述"画面上应该看到什么"**。这个模型对"关系"的遵从度低，
对"看得见/看不见"这种视觉结果反而更听话（同 `simplify_hands` 那次的教训）。

新文案改成三段：

1. 膝盖到哪——"顶到下巴下面"，定住最高点；
2. 小腿往哪折——"向后折叠压在身体和地面之间"，**并且"从正面几乎看不到小腿、也看不到脚"**，
   用"看不见"这个结果堵死"伸出去"那条歧义路径；
3. 整体轮廓——"圆滚滚的团子，外轮廓接近一个球"，给一个可校验的形状目标。

重生成立绘后宽高比从 0.786 变成 0.845，膝盖顶到胸口、脚只露鞋尖。

### 九、已知限制

1. **矩形占位**，不处理实际轮廓。一只杯子会占掉它整个外接框。偏保守——
   宁可多避一点，也不会撞上。
2. **同一行的两件东西分不出先后**（桌上并排的两个杯子）。这时按外接框面积排，
   大的算近。近似。
3. **不处理镂空**：椅子靠背的缝隙会被当成实心。
4. **只挪 x 不挪 y**。`bottom_y` 是"坐在什么高度"，动了它等于换动作；
   横向平移几乎不改变"她在哪、在做什么"。找不到空位时如实报 `conflicts` 并告警，
   不假装修好了。

十个场景是用火山引擎 seedream 生成的测试素材（外网图库在这台机器上不通，
随机图库也没法构造「杯子正摆在桌面正中」这种刁钻构图）。**它们带 AI 痕迹，
只用来验证流程，不能当质量基线。**

|---|---|---|---|---|
| c01 | 咖啡厅木桌 | 杯 + 托盘在正中 | **647px** | 坐到桌子左端，杯盘完整 |
| c02 | 灰沙发 | 坐垫上一本书 | **98px** | 坐着，书露在旁边 |
| c03 | 书桌 | 笔记本 + 马克杯 | **713px** | 坐到桌左缘，电脑完好 |
| c04 | 餐桌 | 正中花瓶 | 25px | 花瓶在中间偏左，她本在右 |
| c05 | 空长椅 | 无（对照） | **0px** | 正确不动 |
| c06 | 空台阶 | 无（对照） | **0px** | 正确不动 |
| c07 | 窗台 | 一盆绿植 | **598px** | 坐到窗台另一端 |

| c10 | 木地板 | 正中一个背包 | **721px** | 换成站姿，站到背包左边 |

**10/10 成品都没有压在障碍物上**，两张对照组的 `moved_px` 都是 0（没有误伤）。

#### 表格里有两个"0px"其实是正确的

c08 / c09 标了"有障碍"却没挪，一开始我判成失败。查下来是**期望表写粗了**：
我把"这张图有障碍"直接当成"她该挪"，但障碍未必在她的落点上。
c09 的规划器把她放在 x=945（画面最右），两个杯子在 607~938——**本来就不重叠**。

这件事的教训：**判据要写成"落点是否与障碍相交"，不能写成"场景里有没有障碍"。**
前者是程序算得出来的，后者只能靠人眼看。

### 十一、这一轮踩的五个坑（都写进了回归用例）

`experiments/step25_avoid_cases.py`，8 条离线用例，0.1 秒跑完。
改任何一条规则先跑它——比跑一轮批量（8 分钟、1.2 元）快几千倍。

| # | 坑 | 后果 | 怎么发现的 |
|---|---|---|---|
| 1 | **`sit_y` 兜底取了框的上沿** | 长椅 `box` 的上沿是**靠背顶**，算出来她"坐在靠背上" | 批量首轮 10 张挪开 0 张 |
| 2 | **深度方向判反** | `base < foot` 被读成"物体更近"，于 c10 里她直接穿过背包 | 批量第二轮，看 c10 成品 |
| 3 | **大件家具当横向障碍** | 桌子 `box=[0,855,999,999]` 横跨全幅，怎么挪都撞 → 永远"挪不开" | 同上 |
| 4 | **给"小物件"设 35% 尺寸门槛** | c01 特写的杯盘各占 44%/54% 宽，被判成"大家具"放过了 | 批量第三轮，c01 挪 0 |
| 5 | **`has_prop` 不可靠** | c09/c02 的 `has_prop` 是 `false`，但 `props` 里有 2 件和 1 件——模型自相矛盾。重试条件只看 `has_prop` 就永远不触发 | 批量第四轮，c02/c09 的 objects 仍为空 |

**共同的教训**：这五条里有四条是**方向/阈值写错**，而且都不是靠读代码发现的，
是跑完一整批图看结果才发现的。根因是几何规则没法用眼睛验——
一张成品出来"看起来还行"，可能只是错的规则恰好没触发。

所以第 25 节那个回归用例文件是这一轮最重要的产出，不是附带品。

### 十二、解析稳定性：端到端可复现性差

同一张 c09，四轮解析给出的 `objects` 分别是 **4 / 4 / 0 / 4** 个。
c02 也一样（3 / 0 / 4 / 4）。`temperature=0.0` 并没有让它稳定。

后果不是"某张图偶发失败"，而是**同一张图跑三次可能给三个不同的位置**。
现在的对策只有"空就重试一次"，能救大部分，但治不了根。

真要治，得换成两次独立解析取交集，或者给 VLM 更结构化的任务（比如按区域扫描）。
在那之前，这条要作为已知限制记着：**端到端结果不完全可复现。**

## 二十六、表情：从焊死在动作里，到独立的一维

### 一、问题：九个动作只有三个有表情，而且都是「笑」

用户的要求是「不同场景不同动作表情也不一样」。扫一遍 `ACTION_LIBRARY` 的
9 个启用动作，表情词是这样的：

| 动作 | 表情词 |
|---|---|
| `shoulder` | 得意地笑 |
| `seat_edge_sit` | 笑得很开心 |
| `jump_air` | 笑得非常开心 |
| 其余 6 个 | **一句都没有** |

而且全是「笑」。所以不管她在空沙发上、在逆光的街边、还是坐在人对面，
脸上永远是同一个笑。

这句话其实有两层意思，第二层是原来的结构根本做不到的：

1. **不同动作要不同表情**——靠动作描述还能勉强写；
2. **同一动作在不同场景也要不同表情**——动作只有 9 个，场景却是千变万化的，
   把表情绑在动作上，就等于永远只有 9 种脸。

### 二、设计：`s3/moods.py`，9 个表情，`face` 写成五官动作

关键决定是**`face` 里不许出现情绪词**。

这个项目的结论已经反复出现过三次（`leg_hug_knee`、`simplify_hands`、
以及上一节的"框的定义"）：**模型对「关系」服从度低，对「画面上能看见什么」服从度高**。

- 写「她很害羞」→ 出来的还是那个笑；
- 写「两颊红得很明显、红晕一直漫到耳朵，眼睛往下看不敢直视，
  下巴微微收着，嘴角抿起来往上翘一点点」→ 才画得对。

所以 9 个表情一律只写五官的具体动作：眼睛是睁是眯、眉毛抬还是皱、
嘴角朝哪、脸颊红不红。`body` 再补身体语言（害羞缩肩、惊讶后仰、得意抬下巴）。

另有 `conflicts` 声明和哪些动作天然冲突（蜷成一团抱膝时做不出"挑眉得意"），
规划器选的时候能看到。

### 三、三次失败，每次都只改了一层

#### 失败 1：把 9 个表情全丢给规划器 → `tender` 占 5/10

第一版直接列出 9 个候选。结果温柔拿了 5 张。

复盘：我把 `when` 写成了「逆光、黄昏、柔和的光线、人物安静地待着」——
**而生活照的光几乎都柔和**。这条判据等于没有区分。

#### 失败 2：把 `when` 改成"她的状态" → `happy` 占 9/10

改成「她正处在兴头上——刚抢到好位置、正要开始玩」之后，更糟了。

因为「她刚坐下，正处在兴头上」**对每张照片都成立**——她确实总是刚找到一个位置。

#### 失败 3：给动作加表情映射 → 直接把多样性抹平

我还加了一条「动作的情绪也要对上：跳/蹦/坐高处 → 偏雀跃或得意；
蜷着抱膝 → 偏害羞或困倦」，结果 10 张测试图全是 `seat_edge_sit`（同一个坐姿），
这条映射把它们**全部导向同一个表情**。

这是个结构性的错误：**用户要的恰恰是"同一动作不同表情"，而动作→表情的映射
天然抹掉这个维度**。

### 四、正解：程序先按场景收窄，规划器只在短名单里挑

三次失败共同的错误是**指望 VLM 自己注意到场景差异**。它做不到——
它总能给最通用的那个选项找到理由。

所以把「场景差异」变成**程序可计算、可测试的量**（`moods.narrow`）：

| 量 | 怎么算 | 推到哪个表情 |
|---|---|---|
| 亮度 | 灰度均值 | 暗 → 困倦/害羞；亮 → 雀跃/惊讶 |
| 色温 | R 均值 − B 均值 | 暖+暗 → 困倦；暖+亮 → 温柔；冷 → 好奇/鼓劲 |
| 对比度 | 灰度标准差 | 硬光高对比 → 惊讶/得意 |
| 饱和度 | HSV 的 S 均值 | 高饱和 → 雀跃；低饱和 → 温柔 |
| 家具语义 | `objects` 的 kind | 床/沙发 → 困倦；吧台/餐桌 → 得意；长椅/台阶 → 好奇 |

**用打分而不是"命中就追加"**。第一版是追加式的，先命中的永远赢——
`sleepy` 同时出现在四条规则里，于是 7/10 张排第一。改成打分后每条规则
给不同权重，让信号互相竞争。

暖光还要**按亮度再分流**：暗的暖光像深夜台灯（困），亮的暖光像黄昏（温柔）。
不分的话它们在每张暖光图里都并列，等于没区分。

短名单收窄到 **3 个**。从 4 个收到 3 个之后，10 张的分布从 3 种变成 4 种。

### 五、实测

**空场景（batch3，10 张 AI 生成的家具照）：4 种**

| 表情 | 张数 |
|---|---|
| 雀跃 | 4 |
| 温柔 | 3 |
| 好奇 | 2 |
| 害羞 | 1 |

**真人物照（batch2，10 张）：7 种** —— 温柔 2、害羞 2、雀跃 2、得意 1、好奇 1、困倦 1、惊讶 1。

**这个差异本身就是结论**：batch3 是空家具，画面里没有任何情绪线索，
模型只能靠光线猜；batch2 有人物、有表情、有事件，线索足够，多样性自然就出来了。

所以「表情够不够丰富」不只是提示词的问题，**也取决于照片本身的情绪信息量**。
空场景里再怎么调提示词也只有 3~4 种合理答案。

### 六、表情画得准不准：因表情而异

用 `mood=` 参数强制指定后逐张验证：

| 表情 | 出来的脸 | 判断 |
|---|---|---|
| `happy` 雀跃 | 眼睛弯成月牙、张嘴笑、脸红 | **准** |
| `curious` 好奇 | 眼睛圆睁、嘴成小 O 形、头歪向一边 | **准** |
| `shy` 害羞 | 两颊通红、眼睛往下看、双手在身前绞着 | **非常准** |
| `smug` 得意 | 一只眼半眯（画成了眨眼）、张嘴笑 | **偏移**：没画出"一边嘴角翘、下巴抬起" |

`smug` 被模型理解成了"俏皮眨眼"。不算难看，但不是描述里的那张脸。
这条要记着：**不是所有表情描述都同样有效**，强表情（害羞、好奇）比
微表情（得意、温柔）更容易画准。

### 七、顺带做的两件事

1. **`moment` 字段**：要求规划器先写一句"这一瞬间她在想什么"（具体的场景感受，
   不许写"她很高兴"这种结论），再从这句话推 `mood_id`。
   实测它写出来的 moment 很有画面感（「暖黄的串灯在身后酒架上晕开软焦光斑，
   两个空玻璃杯刚摆好」），比直接选标签稳。
2. **`run_guided(..., mood=...)`**：允许调用方强制指定表情。
   前端让用户手选、或者批量出图时统一风格都用得上。
   id 拼错不会让整张图失败，退回规划器的选择。
