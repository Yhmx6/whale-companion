## 0. 结论先行

**一、接触阴影不应该交给模型生成，应该程序化算。**

04 号文档说「手工补起来最便宜——一个椭圆选框加高斯模糊」。手工是第二便宜的，程序化才是最便宜的：它能做到零推理成本、可实时预览、可参数化。更重要的是，程序化阴影给了我们一个模型天然没有的东西——**一个显式的光源**。这一条同时治了「缺接触阴影」和「两套光照打架」两项失败形态，因为阴影不再是由另一个模型猜的，而是由同一个光源参数算出来的。

**二、管线需要一个贯穿全链的数据契约：LightingState。**

04 号文档点出了根因：「AI 没有统一的光源概念，它分别学过『明亮人脸』和『布料上的阴影』两种样本，然后强行拼在一起。」治法不是事后调色，是**把光源变成一个显式对象**，从 S1 估计、S2 生成条件、S3 阴影渲染到 S4 质检，全程携带同一个 `LightingState`。这是架构层面的解，调参碰不到。

**三、否决 IPAdapter 堆叠路线，改用 Qwen-Image-Edit-2511 三视图多图。**

理由是需求错位：IPAdapter FaceID 强在**人脸身份**，弱在**服装道具**（社区公认「保不住服装一致性」）。而我们不需要保人脸——鲸鱼娘不是真人，没有身份识别需求。我们要保的是鲸尾、藏青女仆裙、发型配色这些**视觉特征**，恰好是多图参考擅长的。而且白底三视图天然是 3 张，正好压满 2511 的 3 张参考图上限。用 IPAdapter 是把强项用在不需要的地方，把弱项暴露在最要命的地方。

**四、新增一项 04 号文档未列但代价最低的修正：重力方向对齐。**

「一百张里八十张的假感来自肩线胯线角度差 1 至 2 度」——这不是焦段问题，是**角色的竖直轴没有与照片的重力方向对齐**。解法是一个旋转角，纯程序化，成本接近零，命中率却直指最大的一类假感。05 号文档完全漏了这条。

## 1. LightingState：贯穿全链的光源契约

### 1.1 为什么必须是结构化对象，不能是提示词字符串

如果把光向写成自然语言塞进提示词（「窗光从左边照进来」），那么 S3 要渲染阴影时得**再把这句话解析一遍**，解析结果与模型的内部理解不保证一致。这就是「两套光照」在架构层的复现。

正确做法：S1 输出结构化 `LightingState`，S2 把它序列化成提示词，S3 直接读它的字段算阴影。**同一个数值，两个消费者，物理上不可能打架。**

```
LightingState {
  direction:  { azimuth: -35°, elevation: 42° }    // 世界坐标下的主光方向
  quality:    { hardness: 0.72, intensity: 0.86 }   // 硬光/柔光、强度
  color:      { temp: 5200K, tint: +3 }             // 色温，用于角色层调色
  sources:    [ { type: "window", conf: 0.81 } ]    // 多光源时按置信度排序
  gravityDeg: 1.4°                                   // 见第 4 节
  confidence: 0.78                                   // 低置信度触发降级
}
```

### 1.2 怎么估

三级串联，前一级失败降级到下一级：

| 级别 | 方法 | 成本 | 适用 |
|------|------|------|------|
| L1 结构法 | 深度图求法线（Sobel 梯度），在平面区域拟合朗伯模型 `I = ρ(N·L)`，最小二乘解 L | 纯 CPU，几十毫秒 | 有明确平面（地面、墙面、桌面） |
| L2 阴影投票 | 检测照片中已有的阴影边缘方向，对可能的 L 方向做投票 | 需分割，秒级 | L1 置信度低（曲面、镜面） |
| L3 VLM 直读 | Qwen2.5-VL（就是 2511 的文本编码器）直接看图输出结构化光向 | 一次轻量推理 | 前两级都失败，或场景复杂 |

L1 能覆盖约七成照片，这是主力。L3 不是兜底凑数——因为 Qwen-Image-Edit 的文本编码器本来就是 Qwen2.5-VL，让同一个模型先「看光」再「打光」，理解链路是连续的，比换一个模型估光更不容易产生两套光照。

### 1.3 两个必须有的降级出口

- `confidence < 0.5` 时，**不生成投射阴影**，只保留接触阴影（AO 层）。理由见第 2.4 节。
- `hardness > 0.85`（强硬光，如正午直射）时，投射阴影用 4 段而非 3 段渲染，因为硬光下软硬过渡更陡。

## 2. 接触阴影：改为程序化图层

### 2.1 模型只做材质与光照融合，几何精度交给程序

这是一条 prompt 分工决策，也是整个方案里最重要的一个约定：

> **S2 的提示词明确要求「不要生成地面投影阴影」，把阴影留给 S3。**

理由：阴影的**位置、长度、方向、软硬衰减**全部是几何量，可以精确计算；而模型擅长的是**材质、反射、环境色渗透**这些算不出来的东西。让模型去猜几何，是在它最弱的地方赌运气；让它只做材质，是在它最强的地方拿分。

这也是 `ComfyUI-RealProductScene` 那个 3 星仓库给的最有价值的判断——「产品像素 100% 来自原图，AI 不重画产品，只负责它周围的场景、接地与光影」。我们的角色设定图比产品图更需要保真，这个思路应当推到更彻底。

**风险与兜底**：模型可能不听话仍然画了阴影。S4 检测「框底边下方条带是否已存在方向性暗区」，存在则跳过 S3，或先用 mask 清除再渲染。跳过比叠两层好——双重阴影比没阴影更假。

### 2.2 三层渲染参数（治「软硬不分层」）

04 号文档的原话是「真实阴影在接触点最锐、随距离变软、透明度从基座向远端衰减」，需要三层控制。参数化成可执行的规格，`w` = 角色在画面中的底边宽度：

| 层 | 形状 | 长度 | 模糊 sigma | 不透明度 | 混合 |
|----|------|------|-----------|----------|------|
| AO 层（接触遮蔽） | 以接触点为心的椭圆，`a = 0.6w, b = 0.22w` | — | `0.03w` | 0.60 | multiply |
| 近段（锐） | 沿 -L 在地面的投影方向 | `0.8w` | `0.05w` | 0.35 | multiply |
| 中段 | 接上 | `1.6w` | `0.12w` | 0.18 | multiply |
| 远端（软） | 接上 | `2.4w` | `0.25w` | 0.08 | multiply |

`b/a = 0.22/0.6 ≈ 0.37` 这个俯视压缩比由相机俯角决定，从深度图的地平面斜率反推，不能写死。

04 号文档说 AI「给全长度恒定不透明度」看起来像画上去的。上表的不透明度是 0.35 → 0.18 → 0.08 的单调衰减，且模糊递增，这正是「投出来的」而非「画上去的」的数值特征。

### 2.3 为什么这比手工便宜，且改变了产品体验

手工 8 至 12 分钟里，最耗时的环节就是「画阴影 + 调软硬 + 试方向」。程序化后：

- 单次渲染 < 5ms（Canvas 2D 就够，不需要 GPU）
- 用户拖动框时，阴影**实时跟着动**——WYSIWYG
- 光向、软硬、浓度可以做成三个滑块，用户自己微调

这就是「1 分钟的体验里拿到 8 分钟的质量」最直接的抓手。而且它把「返修」变成了「调滑块」，不用重新生成、不花钱、不等待。

### 2.4 原则：宁可不出阴影，也不要出方向错的阴影

错的阴影方向是**可被指认的错误**——用户会立刻说「影子朝右但脸是左光照的」。没阴影只是「有点飘」，仍有相当可用率。

所以 `confidence` 低时降级为只有 AO 层（紧贴接触点的暗部），不画投射方向。AO 层不依赖光向，永远安全。这一条要写进 QC 规则：方向置信度不足时，S4 不应因为「缺投射阴影」而扣分。

## 3. 景深一致性（04 号文档的第 5 项，05 号文档完全漏了）

**一个隐性优势需要先说清楚**：04 号文档列的「二维平面式假虚化」，成因是「AI 训练集里大量『抠好的人物层 + 整张模糊的背景』，它学会了这种取巧模式」。这是**整图重绘**产品的问题——它把背景也重画了，于是虚化程度全画面一致。

我们不重绘背景。用户的照片原样保留，背景虚化天然是对的。**但这不意味着我们没问题，问题换了个形式**：插入的角色层是锐利的，如果用户把框放在远景（原照片该区域是虚化区），锐利的角色插进去会立刻穿帮。

解法：从深度图估计每像素的弥散圆半径（circle of confusion），对角色层做**空间变化的散焦**。

```
CoC(d) = |d - d_focus| / d * (f² / (N * (d_focus - f)))
```

工程上不必精确算光学公式。只要满足单调性——角色所在深度离焦点越远、blur 越大——视觉上就成立。实现上用分层近似：把角色按深度切 3 至 4 个带，各自 Gaussian blur 后用深度做羽化过渡，避免硬边。

**成本**：纯 CPU，几毫秒。**收益**：治掉一整类「怎么看怎么假，说不出哪不对」。

## 4. 重力方向对齐（三项失败形态里最便宜的一项）

### 4.1 把「肩线胯线角度差」翻译成几何问题

04 号文档给的业内口径是「一百张里八十张的假感来自肩线胯线角度差 1 至 2 度」。这句话容易被理解成焦段问题，其实是**重力方向问题**：

人的竖直轴永远指向重力方向。如果照片是仰拍或俯拍，画面里的「竖直」不等于图像的竖直轴。而角色三视图是正交正面图，其竖直轴就是图像竖直轴。直接贴上去，角色的竖直轴与照片的重力方向差了那么一两度——大脑立刻察觉，但说不出哪里不对。

### 4.2 解法：一个旋转角

```
1. 从照片估计垂直消失点（用已有垂直结构：门框、墙角、站立的人物）
2. 由消失点推出重力方向在画面上的投影角 θ_gravity
3. 角色绕其锚点（框底边中点）旋转 -θ_gravity
```

仰拍时 `θ_gravity ≠ 0`，角色跟着倾斜；平拍时垂直消失点在无穷远，`θ_gravity ≈ 0`，不旋转。手机广角近距离仰拍是重灾区，正好是我们的典型输入。

**成本**：一次矩阵旋转，零推理。**这可能是整个方案里性价比最高的一个修正。**

## 5. 角色锚定：Qwen-2511 多图 vs IPAdapter 堆叠

PM 建议对比这两条路线，逐维度列清：

| 维度 | IPAdapter + ControlNet 堆叠 | Qwen-Image-Edit-2511 多图 | 判定 |
|------|----------------------------|---------------------------|------|
| 保人脸身份 | 强（FaceID，权重 0.7-0.8） | 中 | 我们不需要 |
| 保服装/道具 | **弱**（社区公认保不住） | **强**（多图参考直喂） | 2511 胜 |
| 保配色/发型 | 中 | 强 | 2511 胜 |
| 模型数 | 4-5 个（IPAdapter / FaceID / ControlNet OpenPose / FaceDetailer） | 1 个 | 2511 胜 |
| 权重调参 | 逐个调，互相打架（调好 A 坏了 B） | 无需 | 2511 胜 |
| 参考图数量 | 吃单张，浪费三视图 | 最多 3 张，正好压满 | 2511 胜 |
| 姿势控制 | OpenPose 可锁 | 需提示词或额外 ControlNet | IPAdapter 胜 |
| 许可 | 需逐层穿透（InsightFace 部分非商用） | Apache-2.0 单点干净 | 2511 胜 |

**结论：不用 IPAdapter。** 一句话概括理由——我们保的是「这个角色看起来是同一个角色」，不是「这个人是同一个人」。FaceID 保的是后者。用错工具，还顺带把许可搞脏。

### 5.1 三视图的分工建议

2511 的上限是 3 张参考图，白底三视图正好。但要分工而不是重复：

| 参考位 | 喂什么 | 为什么 |
|--------|--------|--------|
| 图 1 | 正面全身 | 主身份锚点，服装配色最完整 |
| 图 2 | 侧面 | 鲸尾的立体形态，正面图看不出来 |
| 图 3 | 特写或背视 | 强识别细节（裙摆纹样、发型后视） |

三张都必须是**抠净的统一底色**（BiRefNet + 去白边）。白底残留会污染生成——这正是 04 号文档 §5.3 提到的「抠图边缘露白」的前置成因。

### 5.2 如果 2511 的服装一致性仍不够

升级路径是 LoRA 微调，不是回到 IPAdapter。理由：Apache-2.0 允许微调和商用分发，50 至 100 张角色官方图即可训一个角色 LoRA，成本一张 GPU 几小时。这条路径的产出是**可复用的资产**，而 IPAdapter 的权重调参是一次性的手活。

## 6. 细节穿帮：用「少重绘」而不是「修得好」来解

04 号文档列的「肩带断开、袖口褶皱方向打架、镜框没有鼻托」这一类，本质是模型不理解物体的机械连接与因果关系。这类问题**修不好，只能少给它犯错的机会**。

策略三层：

1. **能不重绘就不重绘**。角色贴入后，只有框边缘外扩 `0.12w` 的环带允许模型改动（用于环境色渗透和边缘融合），角色内部锁死原始像素。
2. **必须重绘的地方限制幅度**。环带用低 denoise（0.25-0.35），只做色彩与光照过渡，不做形状。
3. **QC 事后抓**。这类穿帮在一个固定视角下可以规则化检测：检测角色 mask 内是否存在亮度突变的高频边缘（肩带断开会产生），以及细长连通域是否断裂。

第 1 条是这条策略的关键——它同时解释了为什么「生成式整图重绘」路线注定打不过「贴图 + 局部融合」：**整图重绘每多改一个像素，就多一次穿帮的机会。**

## 7. QC 打分卡：八项可计算指标

PM 问要不要出可对照的检查清单。要，但**不该是人工打分卡**——人工打分没法做自动排序，也没法做 A/B 数据。

八项全部做成 0 至 100 的可计算分，加权得到最终排序分：

| # | 对应失败形态 | 指标 | 算法要点 | 权重 |
|---|-------------|------|---------|------|
| 1 | 缺接触阴影 | 接触暗区强度 | 框底边下方 0.2w 条带的平均亮度 vs 同图地面基线，要求低 15% 以上 | 高 |
| 2 | 阴影软硬分层 | 衰减单调性 | 对底部条带拟合「暗度-距离」曲线，要求单调递减（均匀软硬给出平线） | 高 |
| 3 | 两套光照打架 | 明暗界面一致性 | 角色 mask 内的亮度梯度主方向 vs `LightingState.direction` 的投影，夹角余弦 | 高 |
| 4 | 阴影方向矛盾 | 阴影轴向一致性 | 检测投射阴影主轴方向 vs 期望方向，夹角 | 高 |
| 5 | 透视/焦段 | 重力对齐残差 | 角色竖直轴 vs 照片重力方向，要求 < 1.5° | 高 |
| 6 | 二维平面式假虚化 | 深度-模糊一致性 | 角色所在深度的期望 CoC vs 实际高频能量，相关性 | 中 |
| 7 | 角色每次不一样 | 特征相似度 | CLIP/DINO 比较角色区域与三视图参考；另加鲸尾+藏青色的定向检测 | 高 |
| 8 | 细节穿帮 | 高频突变计数 | 角色 mask 内亮度二阶导的异常峰值数 | 中 |

**指标 7 的定向检测值得单独做**：通用相似度会漏掉「整体像但鲸尾没了」这种。用颜色直方图检查藏青色占比、用分割检查鲸尾形状是否存在，这两个特征是这个角色的强识别点，也是 04 号文档担心的 IPAdapter 保不住的两处。

**这套卡的另一个用途**：给每个失败候选打标签。用户看到的是排序后的 4 张，我们看到的是「这张失败在指标 1 和 5」。跑 50 张之后，标签分布直接告诉我们管线该先修哪一环——这比凭感觉调参快一个数量级。

## 8. 接口边界：图进图出，不预留对话字段

PM 提到原型阶段不做持续情感互动，以主张不落入《人工智能拟人化互动服务管理暂行办法》（2026-07-15 施行）的适用范围。这在接口契约上要落成**可审计的硬约束**，不是一句注意事项：

| 约束 | 具体要求 |
|------|----------|
| 请求体 | 只允许 `image_url`、`box`、`style`（枚举）、`ref_images`（最多 3）。**禁止**出现 `session_id`、`history`、`messages`、`persona`、`character_id`、`mood` |
| 响应体 | 只返回 `images[]`（含 url 与 scores）。**禁止**返回任何第一人称文本、角色台词、情绪标签 |
| 错误文案 | **不得使用角色口吻**。「呜…我站不进去呢」这类文案就是人设对话流的入口。统一用中性告知：「该位置无法生成，请调整框后重试」 |
| 加载文案 | 同上。用「正在合成」不用「她正在努力」 |
| 状态管理 | 无会话态。每次请求独立，服务端不留用户历史 |

OpenAPI 的 `description` 里要把这五条写进契约，让前端无法无意中引入对话字段。**接口不预留字段，是最便宜的一次合规成本规避。**

## 9. 修正后的管线与排期

### 9.1 管线（相对 05 号文档 §6 有四处变化）

```
S0  预处理：BiRefNet 抠像 + 去白边 + 三视图分工（图1正面/图2侧面/图3细节）
S1  场景理解：深度（DA-V2-Small）+ 地面平面拟合 + 重力方向 + LightingState
    输出：{ depth, groundPlane, gravityDeg, LightingState }
S2  融合生成：Qwen-Image-Edit-2511（三视图多图参考）
    提示词注入 LightingState 序列化结果 + 「不要生成地面阴影」
    改动：只在框外扩 0.12w 环带内允许修改，角色内部锁像素
S3  几何后处理（新增，全部程序化，纯 CPU）
    S3.1 重力对齐旋转（-gravityDeg）
    S3.2 深度匹配散焦（CoC）
    S3.3 接触阴影渲染（AO 层 + 三段投射层，参数取自 LightingState）
S4  QC 打分：八项指标 → 加权排序 → 失败标签
```

四处变化：S1 新增重力方向与 LightingState；S2 加了「不要生成阴影」与局部重绘约束；S3 从「阴影补强」扩成三项纯程序化后处理；S4 从四项指标扩到八项。

### 9.2 排期变化

05 号文档的排期第 1 位是「跑 GPSDiffusion 判生死」。**这条要改。**

理由：既然接触阴影改走程序化，GPSDiffusion 就从「主路径」降为「对照方案」，不再是生死项。程序化阴影的失败模式是可预期的（复杂地面、软体轮廓），而它可以先用规则兜住（降级为只有 AO 层）。真正的生死项换成了 S2——Qwen-Image-Edit-2511 在「三视图 + 二次元 + 写实照片」这个输入下的框位遵从率与角色漂移率。

| 新顺序 | 动作 | 成本 | 判什么 |
|--------|------|------|--------|
| 1 | Qwen-2511 API + 自托管，同一批 30 张跑对照 | 1 天 + API 费 | 框位遵从率、漂移率、单张成本。**这是新的生死项** |
| 2 | 实现 S3 三项程序化后处理（旋转/散焦/阴影） | 2 天 | 纯 CPU，能立刻看到「贴上去 → 站住了」的差值 |
| 3 | 写 S4 八项 QC | 2 天 | 打分与人工观感是否一致 |
| 4 | 跑 GPSDiffusion 做对照 | 半天 | 程序化阴影 vs 模型阴影，谁的地面处理更好 |
| 5 | 决定要不要动 IC-Light / AnyDoor | — | 前四步够用就不碰 |

**第 2 步值得单独强调**：它不依赖 GPU、不依赖模型效果、不需要等别人，两天能做完，而且做完就能拿到「返修率从 35% 降到多少」的第一个硬数据。**这是当前投入产出比最高的一件事。**

## 附：对 04 号文档八项失败形态的覆盖核对

| # | 04 号文档失败形态 | 本文对应节 | 解法性质 |
|---|-------------------|-----------|----------|
| 1 | 两套光照打架 | §1 LightingState | 架构层（同一光源两处消费） |
| 2 | 缺接触阴影 | §2 程序化 AO 层 | 程序化（几何可算） |
| 3 | 阴影软硬不分层 | §2.2 三层参数 | 程序化（单调衰减） |
| 4 | 阴影方向与身上明暗矛盾 | §1 + §2.4 | 架构层 + 降级策略 |
| 5 | 二维平面式假虚化 | §3 深度匹配散焦 | 程序化（我们重绘范围小，风险形式不同） |
| 6 | 透视/焦段不匹配 | §4 重力对齐 | 程序化（一个旋转角） |
| 7 | 角色每次长得不一样 | §5 Qwen-2511 多图 + LoRA 升级路径 | 模型选型 |
| 8 | 细节穿帮 | §6 少重绘策略 | 流程约束（不改，只限改动范围） |

八项全部有对应解法。其中五项（2、3、5、6 及 1 的一半）是**程序化**的——这意味着它们不消耗推理成本、不受模型版本影响、可实时预览。这也是本文最重要的一个判断：**「写实融合」这件事里，能被精确计算的部分比想象中多，而把可算的部分交给模型去猜，是这个品类返修率高的重要成因。**
