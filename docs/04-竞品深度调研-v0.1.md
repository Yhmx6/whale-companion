# 竞品调研 · 「把虚拟角色放进我的真实照片」· v0.1

> 调研问题：市面上有没有产品在做和我们同一件事？做到什么程度？失败在哪？
> 日期：2026-10-26
> 关联文档：《可行性评估与技术方案 v0.1》《PRD v0.1》
> 方法：联网检索公开报道、应用商店页面、厂商新闻稿、用户评论与失败案例复盘。所有产品名与平台均为检索中真实出现，未核实项单列第 7 节。

## 1. 结论先行

**这个需求方向有人在做，但没有一个产品把「我们要做的这三件事」同时做对。**

拆开看，我们要同时满足三个条件：

| 条件 | 含义 |
|------|------|
| A. 角色一致 | 每次出图都是同一只鲸鱼娘，不是每次重画一个新角色 |
| B. 写实融合 | 和真实照片同一套光源、有接触阴影、透视匹配，不像贴纸 |
| C. 位置合理 | AI 读懂场景，把她放在路边、长椅、树下、桌面，且接触面对得上 |

现有产品普遍只满足其中 1 至 2 个：

| 产品类型 | A 角色一致 | B 写实融合 | C 位置合理 |
|----------|-----------|-----------|-----------|
| AI 陪伴类（筑梦岛 / 猫箱 / 星野） | 满足 | 不满足（多为二次元贴图或情绪卡片） | 用户手动摆，不自动 |
| AR 相机类（hololy / WEE / 猫箱 AR 投射） | 满足 | 半满足（有实时投影感但无场景光影重建） | 用户手动摆 |
| 写真类（秒画趣拍 / 妙鸭 / 醒图） | 满足（对真人脸） | 半满足（整图重绘，非"插入"） | 不需要 |
| 海外换脸/情侣照（Remini / Pose AI / Photify） | 满足（对真人脸） | 部分满足 | 不需要 |
| 通用生图（ChatGPT / 即梦 / ComfyUI） | 需用户自己解决 | 需用户自己调 | 需用户自己写提示词 |

**A + B + C 三项全中的产品：0 个。**

空档就在这里。但不是"没人想做"，而是"做对 B 很难，做对 C 很难，同时做对 A 更难"。第 4 节把难点拆开了。

### 2.3 失败的第三方：Meta Muse Image（反面教材）

| 项目 | 内容 |
|------|------|
| 产品名 | Muse Image（Meta Superintelligence Labs） |
| 平台 | Meta AI App / Instagram / WhatsApp |
| 能力 | 在提示词里 @ 一个公开 Instagram 账号，即可抓取该账号公开照片作为素材，生成"把真人放进任意场景"的图片 |

2. 被美国消费者组织 Public Citizen 称为"对用户隐私的肆意侵犯"，Privacy International 批评"AI 公司把人们的图像当作可榨取的原材料"
3. 美国国家反性剥削中心指出其可成为性勒索与诈骗工具
4. 好莱坞经纪公司 CAA 提出抗议

**判断**：这是全篇最重要的一条边界。**把真人放进图里 = 极高法律风险；把一个明确虚构的角色放进用户自己的照片里 = 风险低一个数量级。** 我们的产品定义天生站在安全侧，这是可以写进宣传的差异点。

## 3. 替代方案（用户不用我们时，实际怎么干）

### 3.1 自建 ComfyUI 工作流（最硬的替代）

| 项目 | 内容 |
|------|------|
| 典型路径 | 本地 ComfyUI：SDXL 写实底模 + IPAdapter FaceID（权重 0.7 至 0.8）+ ControlNet OpenPose（权重 0.3 至 0.5）锁姿势 + FaceDetailer 修脸（denoise 约 0.4）；或 Qwen-Image-Edit 多图输入做角色迁移 |
| 云端版 | RunningHub 已上架现成模板「穿越二次元和主角们合照」：上传你的照片 + 输入动漫名，选比例分辨率，点运行。官方页面公示：近期运行成功率 92%，平均运行时长约 93 秒，1K 分辨率每天免费 5 张 |
| 门槛 | 本地要显卡 + 装自定义节点 + 调权重；云端要注册 + 理解模板参数 |
| 产物质量 | 高手能做出可用图，但需要**逐张手工校验光影方向、接触阴影、透视**。业内实测口径：一键合成返修率 35% 以上，手动分层合成返修率约 8% |

**对我们的意义**：替代方案的天花板已经被验证了——技术上完全可行，且已有现成模板跑通。用户不选它的唯一理由是"太麻烦、太慢、要调参"。**这就是我们产品的存在理由：把 8 分钟的手工活变成 4 步点击。**

### 3.2 ChatGPT / 即梦 / Dreamina 生图后手动拼

| 项目 | 内容 |
|------|------|
| 路径 | 先用文生图生成角色图，再抠图贴到照片上，或反复用图生图试图融合 |
| 致命缺陷 | 行业对比文章明确指出：identity lock（身份锁定）需要**一张脸的照片**，而不是一段文字描述。纯文生图无法稳定复现一个虚构角色的长相 |
| 产物质量 | 双重失败：角色每次长得不一样 + 贴上去没有光影融合 |

### 3.3 贴纸 / 模板类工具

初音未来激萌相机（官方授权，AR 贴纸相机，初音贴纸跟随人脸、出现在生活场景）、Picsart 贴纸、各类"动漫合影"模板。产物是平面贴纸质感，无接触阴影、无光源统一。**用户要的"她真的在"这一层，贴纸永远做不到。**

### 3.4 约稿画师

传统做法，成本高、周期以天计。它证明这是真实需求（有人愿意花钱），但也说明现有供给远远不够。

## 4. 差评与失败形态解剖（本文最有价值的部分）

失败分成三类，且**技术失败是可修的，商业失败和合规失败是致命的**。

### 4.1 技术失败：为什么"看起来像贴上去的"

这是这个品类的核心技术痛点，已有系统性复盘：

| 失败形态 | 具体表现 | 成因 |
|----------|----------|------|
| **两套光照打架** | 人脸完全受光，但身侧/背景有明显的方向性阴影，物理上讲不通 | 人物主体光照与环境光照是**分别生成**的，AI 没有统一的"光源"概念，它分别学过"明亮人脸"和"布料上的阴影"两种样本，然后强行拼在一起 |
| **缺接触阴影（最致命）** | 脚底没有压紧的暗部，人像"悬空五公分" | AI 经常省掉物体与地面接触处那一圈小而深的遮蔽区。这一圈是"重量感"的唯一来源，缺了它大脑立刻报警 |
| **阴影软硬不分层** | 影子要么整条一样虚、要么整条一样实 | 真实阴影在接触点最锐、随距离变软，AI 常常给均匀的软度或均匀的锐度 |
| **阴影方向与身上既有明暗矛盾** | 影子朝右，但脸上高光在左上 | 模型不知道原照片里已经"烤进去"的光向 |
| **二维平面式假虚化** | 砖块、灯具、窗帘虚化程度完全一致 | AI 训练集里大量"抠好的人物层 + 整张模糊的背景"，它学会了这种取巧模式，复现出来。<br>**注意：这是"整图重绘"产品的问题，我们的风险形式不同**——我们不重绘背景，背景虚化天然正确；但**插入的角色层是锐利的**，若框落在远景（原图该区域本该虚化）就会穿帮。解法是深度匹配散焦（按 CoC 分层 blur），纯 CPU 几毫秒。不能因为"我们不重绘背景"就误判为"我们没有这个问题" |
| **透视/焦段不匹配** | 怎么看怎么假，说不出哪不对 | 手机广角畸变与生成的默认人像焦段假设不一致，人物与环境的投影关系对不上 |
| **重力方向未对齐**（原归因修正，见下） | 角色看起来"斜着插"进画面，说不出哪不对 | **原文档把"肩线胯线角度差 1 至 2 度"归因于焦段，是错的，真因是重力方向。** 人的竖直轴永远指向重力方向；仰拍俯拍时画面里的"竖直"不等于图像竖直轴；而三视图是正交正面图，竖直轴就是图像竖直轴。直接贴上去就差那一两度，大脑察觉但说不出。解法：从照片估垂直消失点 → 推出重力方向在画面上的投影角 → 角色绕框底边中点反旋。一次矩阵旋转，零推理 |
| **角色每次长得不一样** | 连出两张，发色、裙装主色都变 | 没有做角色级 LoRA 或稳定参考锚定，每次重 roll 一个新角色 |
| **细节穿帮** | 肩带断开、袖口褶皱方向打架、镜框没有鼻托、镜片无反光 | AI 不理解物体之间的机械连接与因果关系。这类隐蔽穿帮比明显崩坏更伤——用户是在上架/发布之后才被指出来 |

**这一节直接对上了 PRD 的 AC-12（接触面贴合）与 AC-13（主光方向 + 接触阴影）**。这两条不是锦上添花，是这个品类的生死线。

**归因修正记录（2026-10-26，经架构师提出、产品侧采纳）**：
- 原第 6 项把"肩线胯线角度差 1 至 2 度"归因为焦段问题，**真因是重力方向未对齐**，已拆为独立一项。这一项是全文九项里修正成本最低的（一次矩阵旋转，零推理），也是最容易被误判为"模型能力不够"而放弃的
- 原第 5 项（假虚化）的风险形式对我们发生了变化，已在表内注明
- 因此本文失败形态从八项扩为**九项**。架构师在《06-管线设计与失败形态映射 v0.1》中对九项逐一给出了对应解与可计算指标

## 5. 我们的差异化空间

不是"没人做"，是"**每个人都在做半个，且都卡在不同的坎上**"。四个可打的位置：

### 5.1 位置一：唯一同时做对 A + B + C 的产品

- 陪伴类产品解决了 A（角色一致），放弃 B、C
- 写真/换脸类产品解决了 B 的部分（整图重绘有统一光影，但代价是"改掉了我的照片"），放弃 C
- AR 类产品解决了 A，B 靠 3D 模型硬贴（没有接触阴影），C 全靠用户手动摆

**我们的空档：不改用户的照片，只往里加一个人，且这个人有影子。**

这是最难的一档，也是最难被"巨头顺手整合"的一档——因为它不是模型能力，是管线工程（场景理解 + 光源判定 + 接触面推理 + 局部重绘 + 精修）。

### 5.2 位置二：把"禁忌品"变成"可炫耀的日常"

YouCam 自己写"请勿发布到社交平台"。hololy 只能靠粉丝投稿。Meta 的直接下线。

所有这些产品都没能解决一个心理问题：**"我发这张图，别人会觉得我怪吗？"**

我们的设定天然更安全：鲸鱼娘是**明确虚构的角色**，不是真人，不需要"她真的存在"这种欺骗性叙事。用户发朋友圈的文案可以是"我的鲸鱼娘今天陪我来爬山"，这是玩梗，不是造假。**这是我们可以公开讲、也可以让用户骄傲地讲的差异点。**

### 5.3 位置三：从"一次性出图"转向"她的生活流水账"

妙鸭死于"一年用一次"。hololy 死于"角色不够多所以腻了"。

两者指向同一个解法，但方向相反：
- 妙鸭的问题不是图不够好，是**没有下一次打开的理由**
- hololy 的问题是想靠"不断加新角色"续命，但供给速度永远追不上用户消耗速度

**正确解法是：一个角色，无限场景。** 角色数量不需要增长，需要增长的是"她今天可以出现在哪里"。用户的相册是每天更新的，她的出场机会就是每天更新的。这是唯一能做到高频的结构。

### 5.4 位置四：合规成本结构性更低

| 维度 | 我们的情况 |
|------|-----------|
| 肖像权 | 用虚构角色，不碰真人肖像。规避 Meta 的死法 |
| 内容风险 | 单角色、无暧昧人设、无对话功能（原型阶段）。规避筑梦岛的死法 |
| 拟人化互动监管 | 原型阶段只做"生成照片"，不做持续性情感互动，可主张不落入《暂行办法》适用范围 |
| 标识义务 | 显式 + 隐式标识必须做，PRD 第 7 节已覆盖 |

## 6. 对 PRD 的具体建议

| 建议 | 依据 | 对应 PRD 条目 |
|------|------|--------------|
| 接触阴影与主光方向必须列为 P0 验收项，不可降级 | 这是全品类最集中的失败点，缺了它产品直接变成贴纸 | AC-13 已覆盖，维持 P0 |
| 增加"重力方向对齐"作为质量检查项 | 业内实测：80% 的假感来自肩线胯线角度差 1 至 2 度，**真因是重力方向而非焦段** | 建议 AC-12 补充"角色竖直轴与照片重力方向夹角 < 1.5°"（原表述"肩线角度与场景透视一致"归因不准，已修正） |
| 候选数量 4 至 6 张是对的，不要削减 | 写实融合单张成功率天然低，必须靠数量兜住 | AC-07 维持 |
| 把二次生成率作为核心北极星指标之一 | 妙鸭死于"没有下一次"；二次生成率高说明质量不行，二次生成率极低且首轮命中率高才是健康 | 已在 8.2 节列出 |
| 原型阶段就明确"不发社交"与"要发社交"的边界 | YouCam 因误导性主动劝退传播；我们的角色虚构属性天然可传播，这是核心卖点，应在设计上体现（如结果图周围留出可配文的边距） | 建议加入产品定位章节 |
| 角色库策略：不做角色数量扩张，做场景/姿势扩张 | hololy 死于供给速度追不上消耗速度 | 与 F-09 姿势模板方向一致，建议明确写成策略 |
| 用户协议与退款政策从第一天就干净 | 妙鸭被上海市消保委点名的直接原因 | 第 7 节合规表可补充退款条款说明 |
