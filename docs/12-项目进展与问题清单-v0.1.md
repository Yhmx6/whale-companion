## 零、主路线：引导生成（2026-10-27 决定）

**引导生成（`route="guided"`）成为项目主选**，立绘路线降为"精确尺寸档"。
代码里的变更：`run()` 新增 `route` 参数（默认 `guided`），`app/server.py` 透传
`route` 和 `mood`；`run_guided` 新增 `action=`（前端手选动作时收窄候选，
但仍由规划器填位置和表情）。

### 三条路线的现状

| route | 走哪条 | 成本 / 耗时 | 尺寸 | 遮挡 | 表情 | 避让 |
|---|---|---|---|---|---|---|
| **`guided`（默认）** | 场景规划 + 引导图重绘 | 0.12 元 / **16~22 秒** | 偏大 1.13~1.78 倍 | 有 | 9 种 | 有 |
| `sprite` | 立绘 + 程序化合成 | **0 元 / 3~5 秒** | **精确** | 无 | 1 种 | 无 |
| `planned` | 纯规划直出（对照组） | 0.12 元 / 20~40 秒 | 失控 1.7~2.8 倍 | 有 | 无 | 无 |

守住：`experiments/step29_routes.py`（8 条分派用例，0 成本 0.2 秒）

### 这个决定的代价，必须写下来

| 维度 | 换成 guided 之前（sprite） | 现在（guided） |
|---|---|---|
| 单张成本 | 0 元 | **0.12 元（从 0 变成非 0）** |
| 单张耗时 | 3~5 秒 | **16~22 秒（约 4 倍）** |
| 60cm | 精确 | **做不到**（1.13~1.78 倍） |
| 可复现性 | 确定性（同样输入同样输出） | **不确定**（同一张图跑三次可能三个位置） |
| 表情 | 1 种 | 9 种 |
| 遮挡互动 | 无 | 有 |
| 避开障碍物 | 无 | 有 |

**换句话说，这次是用"成本 + 延迟 + 尺寸精度"换"表现力"。**
什么时候该切回 `route="sprite"`：需要精确 60cm、需要批量出图、或者调试
非表现力相关的问题（几何/阴影/抠图）时——那些问题用 0 元的 sprite
路线复现快得多。

## 一、一句话现状

**立绘路线（0 元 / 3~5 秒）是主线，引导生成路线（0.12 元 / 16~20 秒）是精细档。
两条不是"新的取代旧的"，而是明确分工：**

| | 立绘路线 | 引导生成 |
|---|---|---|
| 60cm 尺寸 | **精确**（程序 resize） | 做不到，偏大 1.13~1.78 倍 |
| 遮挡互动 | 无（`behind` 类除外） | 自然，真被人挡住 |
| 表情 | **只有一种**（焊在 png 上） | 9 种，按场景选 |
| 落点避让 | 无（贴哪算哪） | **有**（2.5D 场景图 + 碰撞避让） |

**这轮补上的两块能力：**

1. **她不再坐到咖啡杯上。** 新增简易 2.5D 场景（`s3/scene3d.py`）：
   解析照片时顺带拿到物品清单（含杯子/书/手机这些小物件）、每个物体的接地线、
   可坐面，然后拿她的框去撞一遍，撞上了就沿横向挪开。
   10 张新场景实测：**10/10 成品都没压在障碍物上**。

2. **脸上不再只有一种笑。** 表情从动作里拆出来独立成维度（`s3/moods.py`，9 种），
   由程序按场景收窄候选、规划器在短名单里挑。
   真实人物照 10 张出 **7 种**表情；AI 生成的空家具照只有 4 种——
   **这个差距本身是结论**：空场景里没有情绪线索，再怎么调提示词也只有 3~4 种合理答案。

**三条硬结论（都是这轮打出来的，别再试）：**

- **60cm 在生成路线上做不到**：提示词、引导图尺寸、纯色剪影三条路全失败，
  模型对"卡通小人"有约 26~30% 画面高的尺寸下限（docs/11 §二十四）。
- **这支 API 不支持 mask 局部重绘**：传了返回 200 但静默忽略。
- **VLM 解析不稳定**：同一张图的 `objects` 四轮给出 4/4/0/4 个。
  **端到端结果不完全可复现**，现在只靠"空就重试一次"兜着。

## 三、已经解决的（按类归并）

每一条都附带"靠什么守住"，避免以后再悄悄退回去。

### 3.1 几何与尺度

| 问题 | 根因 | 现在 |
|---|---|---|
| 尺度归一从来没执行过 | `character_mask` 只用蓝色主导 → 户外蓝天被算成角色 → 包围盒贴边 → 归一被**静默**放弃 | 掩码 = 蓝色主导 **∩** 差分；归一入口对"贴边"显式报错 |
| 座面检测框到"沙发 + 茶几" | 问的是"座面框"，模型给整件家具 | 改问"坐垫朝外那一面的竖立框，取上沿" |
| 蹲/跳/盘腿尺度用错 | 以为蹲下包围盒会变矮，给了 0.19 | 实测 raw 包围盒差 5% 以内 → 统一 0.26 |
| 悬空姿态影子贴脚 | 一律用包围盒底边当接触点 | 引入 `lift_ratio`：落点抬起、阴影留在地面 |
| 物件路线可用座面为空时崩 | 列表取 `[0]` | 改 `ValueError` + 友好文案，`run_sprite` 捕获 |

守住：`experiments/step8_e2e_replay.py`（回灌，0 成本）

### 3.2 抠图与透明

| 问题 | 根因 | 现在 |
|---|---|---|
| 她半透明、下半身消失 | alpha 用核心掩码（最紧），只覆盖蓝色部分 | 包围盒用核心掩码、**alpha 用差分幅度**（最全），两级阈值 45 / 22 + 只填封闭空洞 |
| 内部空洞 15.5% / 18.8% | 内部阈值 45 太高 | 内部空隙降到 7.6% / 9.8%；白底立绘路线只有 1.8~4.5% |
| `floodfill` 静默失效 | `PIL.ImageDraw.floodfill` 在 1024×1536 上一个像素都不填（10×10 正常） | 自实现 numpy 迭代膨胀 `_flood_from_border` |

### 3.3 光照与阴影

| 问题 | 根因 | 现在 |
|---|---|---|
| 她身上一条横贯暗带 | `contact_core` 把"她占了哪些列"当成"整列都要压暗" | 她身上清零（膨胀 1px）+ 横向也做高斯（原来是硬边矩形） |
| 地面姿态出现硬边暗条 | 同上，只因座面时被她挡住看不见 | 横向改一维高斯 |
| 立绘路线错用启发式掩码 | 明明有 alpha，却调 `character_mask`（漏白肚皮白鞋） | 直接用立绘 alpha |
| 「她是平的」 | 立绘是中性棚拍光，`match_ambient` 只做直流平移 | 沿光向叠明暗梯度，保能量 + 按 alpha 羽化 + 色温从照片量 |
| 光向判反 | VLM 在 `s04_full` 上把"光从右来"说成"从左来"（树影和投影都朝左倒） | 方向改由画面横向亮度差决定（`side_light`），VLM 只贡献硬度 |
| 明暗与影子不同向 | 重打光信画面、阴影信 VLM | 两者共用一个方向（`shadow_az`） |
| 阴影盖在她身上 | 合成顺序违反 `render_shadow_matte` 自己的契约 | `shadow_under`：只从"她没盖住的那半"里减掉阴影 |
| AO 椭圆躲在她身后 | 半轴 0.42w → 全宽 0.84w，比她本人还窄 | 按"接触面以下还剩多少她"放宽到 0.63w |

守住：`step10_contact_core.py`、`step11_relight.py`、`step12_shadow_dir.py`、`step13_shadow_layer.py`

### 3.4 鲁棒性 / 提示词

| 问题 | 现在的做法 |
|---|---|
| 模型画出两个小人 | `empty_scene` 单独措辞 + 正向数量要求 |
| 无人照片不回光向 | `PROFILE_SYS` 原文"给你一张**人物照片**"、结尾"没有人就输出 `framing:none`" → 无人照直接跳过 `light`。物件路线全是无人照，所以光向永远是 None |
| A/B 结果不可信 | 多次运行各自调 VLM，光向/座面框都在变 → 实验必须**冻结 VLM**（唯一变量原则） |
| 规划器把背包当座面 | 加了「动作 × 场景」一致性校验（`_validate_action_vs_scene`）：坐姿动作必须真的有 `sit=True` 的物体，没有就降级成站姿 |

### 3.5 场景与落点（2026-10-27 新增）

| 问题 | 根因 | 现在 |
|---|---|---|
| **她坐在咖啡杯上**（p04） | 落点只有一个 `center_x`，程序不知道那儿有东西 | 简易 2.5D 场景（`s3/scene3d.py`）+ 横向碰撞避让 |
| **抱膝立绘的腿过长**（p05） | 立绘描述只写了姿态关系（"折在大腿下面"），没写画面结果 | 改成"正面几乎看不到小腿和脚 + 轮廓接近一个球"，重生成 |
| 落点悬在座面上方 | 规划器给的 y 和真实座面差 100~170px，匹配不上就反被判成障碍 | `snap_to_surface`：差额在她身高 75% 以内就吸到座面 |
| 家具横跨全幅当障碍 | 桌子 `box=[0,855,999,999]`，怎么挪都撞 → 永远"挪不开" | 四道筛子：不撞人员、不撞横跨 85% 的面、坐在上面时家具不算障碍、**不是家具的东西一律躲** |
| `sit_y` 兜底取了框上沿 | 长椅框的上沿是**靠背顶** | 改成 `y1 + 0.60 × 高`（地面到座面约是家具高度的 55~65%） |
| **避让规则连错 5 处** | 方向/阈值写错，且**几何规则没有肉眼可验的中间结果**——成品"看起来还行"可能只是错的规则恰好没触发 | `experiments/step25_avoid_cases.py`：8 条离线用例（数据抄自真实 VLM 输出），**0.1 秒跑完**，比跑一轮批量快几千倍 |

守住：`step25_avoid_cases.py`（8/8）、`step24_batch3.py`（10 场景批量）、`step23_make_scenes.py`（造测试素材）

### 3.6 表情（2026-10-27 新增）

| 问题 | 根因 | 现在 |
|---|---|---|
| **9 个动作只有 3 个有表情词，且都是"笑"** | 表情焊死在动作描述里 → 永远只有 9 种脸 | `s3/moods.py`：9 个表情独立成维度，由规划器按场景选 |
| 选出来全是一个表情 | 指望 VLM 自己注意到场景差异，它做不到（"她刚坐下、正处在兴头上"对每张都成立） | **程序先按场景收窄**（像素统计 + 家具语义打分，取前 3），规划器只在短名单里挑 |
| 表情描述不管用 | 写"她很害羞"→ 出来还是那个笑 | `face` 里禁止情绪词，只写五官动作（眼睛怎么睁、嘴角朝哪、脸红不红） |

守住：`step27_mood_pick.py`（零成本验多样性）、`step28_mood_grid.py`（四表情对比图）

## 四、未解决（按优先级）

### P0 — 直接影响体验

1. ~~两次 VLM 调用占了 95% 的耗时~~ — **已解决**（见 docs/11 §十九）。
   座面框并进同一次画像，物件路线从 2 次调用降到 1 次；顺手把两个 CPU 热点
   （`match_ambient` 2.2s、`_qc_scores` 1.0s）也修了。

2. **生成路线的尺寸下限（2026-10-27 新增，最重要的未解决问题）**
   用户规定她 60cm。程序换算得准（`person_h × 60/175`），但生成模型不服从：
   六次客观测量（`s3/measure.py`，逐像素 diff）全部偏大 1.13~1.70 倍（中位 1.60），
   实测值落在 30.7~44.8% 画面高，**没有一张低于 30%**。
   三条控制手段全试过：提示词硬约束、引导图里把她缩小一半、换成纯色剪影要求
   "填满形状"——全部无效。接口也不支持 mask（传了返回 200 但静默忽略，
   两个矩形都被替换）。
   现在的处理：`GUIDED_SIZE_FLOOR = 0.30` 提前告警 + 每次实测返回
   `measured_pct` / `size_err`。**要精确 60cm 只能走立绘路线。**

3. **物件路线尺度不一致**
   同一批素材实测：长椅 19.7%、客厅沙发 20.0%、餐桌 **34.5%**（画面高占比）。
   两把"尺子"（`SEAT_H_FRAC` 画面比例 + `SEAT_W_RATIO` 座面宽度）都是经验常数，
   换一批素材就漂。真正的问题是"照片里没有绝对尺度参照"，现在不假装能算出来。
   （引导生成路线的物件支路也继承了这个缺口，`size_basis=percent_estimate`。）

4. **VLM 解析不稳定（2026-10-27 新增，最影响可复现性的一条）**
   同一张 c09 吧台图，四轮解析给出的 `objects` 数量是 **4 / 4 / 0 / 4**，
   c02 沙发也一样（3 / 0 / 4 / 4）。`temperature=0.0` 并没有让它稳定。
   后果不是"某张图偶发失败"，而是**同一张图跑三次可能给三个不同的位置**。
   现在只靠"objects 空就重试一次"兜着（触发条件还踩过 `has_prop` 会误报 false 的坑）。
   真要治，得两次独立解析取交集，或者按区域扫描。

5. **规划器抖动**
   同一张 p05 连问三次，给出三个不同的动作（`seat_edge_sit` / `leg_hands_behind` /
   `leg_hug_knee`），三个都说得通但每次不同。`temperature` 已是 0.2，
   要收敛得加"优先级规则"（有座面优先坐座面、有人物腿优先腿边动作）。
   表情也有同样的抖动。

6. **`run_guided` 没接进 API / 前端**
   现在只有 `experiments/step19_guided_e2e.py` / `step24_batch3.py` 能跑。
   配方已验证，接线没做。表情的 `mood=` 参数同理。

7. **立绘路线没有表情**
   `run_sprite` 贴的是预生成的 png，脸是画死在那张图上的。
   要支持得按「动作 × 表情」缓存变体（每张 0.12 元，一次性），
   而且生成时**必须把 base 立绘当参考图**传进去，否则姿态会漂。

8. **场景内路线还停在旧架构**
   `shoulder` / `peek` / `hem_peek` 三个动作：角色由模型画、尺度和位置不可控、
   阴影仍盖在角色身上、没有重打光。它们是唯一还要花钱和等 20~40 秒的路径。

### P1 — 影响"像不像"

9. **散光 / 顶光场景没有重打光**（长椅、客厅沙发都是 `flat`/`top`）
   这时她仍然是"平的"。指令里明确不做是有意的（立绘自带顶光烘焙明暗，
   再叠一层是重复打光），但这意味着"贴纸感"在这类场景里没有改善。
   这类场景缺的可能是**对比度 / 饱和度匹配**，不是方向光。

10. **暗面只有亮度变化，没有"失去高光"**
    真实侧光下背光侧会掉饱和度、压暗部细节。现在只是整体乘一个系数。

11. **接触暗核与 AO 的强度配比没有标定**
    横向散开后，暗核峰值从 86 掉到 ~42 灰阶。这个数不该单独调——
    它和 AO 是一件事，得一起在一批金标准上回归。

12. **避让只挪 x，不检查"支撑面还在不在她身下"**
    实测 c07 窗台：为了躲绿植横向挪了 582px，结果她被推到窗台最左端，
    多半个身子悬在窗台外面。挪动时没有回头验证"落点还在不在那个面上"。

13. **`smug`（得意）画不准**
    强制指定的四张里，`shy` / `happy` / `curious` 都准，`smug` 被画成"俏皮眨眼"，
    没画出"一边嘴角翘、下巴抬起"。强表情比微表情好画。

### P2 — 已知但暂不动

14. `shadow_angle_deg()` 里 `+12°` 的地面透视偏置是拍的常数。
15. 手部问题（L2 接触关系层）：只在**设计上绕过**（只选"手天然处于遮挡位"的动作），
    坐标定位重绘实测可用（+0.12 元/次）但没接入。
16. **2.5D 场景的边界**：矩形占位（不处理真实轮廓）、同深度排序靠面积近似、
    不处理镂空（椅子靠背缝隙会被当实心）。
17. **没有金标准集**。所有参数（AO 0.42、BO 0.30、暗核 0.035、重打光 0.10+0.16×h、
    表情收窄的 0.12 / 0.35 / 0.65）都是在 5~10 张图上定的，缺 50~100 张的回归基线。

## 五、可优化的方向

### A. 立刻能做（低成本、收益明确）

1. **`run_guided` 接进 API / 前端**。配方已经全部验证过，接线是纯工程活。
   接的时候把 `mood=` 也一起暴露出去（让用户能手动选表情）。
2. **立绘路线接表情**：按「动作 × 表情」缓存变体，用到才生成（0.12 元 / 张）。
   生成时把 base 立绘当参考图传进去，避免姿态漂。9 个动作 × 9 个表情全量预生成
   是 9.7 元 / 13 分钟，按需生成更省。
3. **避让加上"支撑面校验"**：横向挪完回头看一眼，落点还在不在那个面上。
   c07 窗台就是因为没查这一步，把她推到了窗台外面。
4. **`smug` 的描述改一版**：现在画成眨眼，改成"两边嘴角明显不对称，一边高一边低"试试。

### B. 需要投入

5. **解析稳定性**：同一张图 `objects` 会在 4 和 0 之间跳。两条路——
   两次独立解析取交集（成本 ×2），或按区域扫描（需要新的提示词设计）。
   这是**端到端可复现性**的前提，不做的话所有对比实验都要打折扣。
6. **建金标准集 + 参数回归**：50~100 张，人评 1~5 分，
   回归 AO / 暗核 / 重打光 / 表情收窄阈值四组参数。现在这些数都是"看起来对"。
7. **暗面处理**：把 gain 同时作用到饱和度和局部对比度上，而不只是亮度。
8. **坐标重绘接入手部**：只改手部小块区域，+0.12 元/次，
   需要可靠的手部框（MediaPipe Hands / DWPose，或让用户点）。

### C. 有负结论，不建议再试

- **用 HandRefiner 修手**：官方 FAQ 明说没在卡通图上训练过；且它修的是手指数量（L1），
  我们遇到的是接触关系（L2）。硬数据：抓握成功率 HandRefiner 61% vs GraspDiffusion 98%。
- **"简化手"提示词**：验证过，无效且有害。
- **让模型直接在场景里画角色**：尺度方差不可控，这正是架构转向的原因。
- **单独调接触暗核的强度**：必须和 AO 一起标定。
- **拿"背景环对比度"当光向的真值**：纵向梯度 63~78% 来自内容（草地/水泥地、天空/衣服），
  不是光。

**2026-10-27 新增八条负结论（都是实测的，附数据）：**

*尺寸（四条）*

- **在提示词里把尺寸写得再硬也没用**。把"外接框大小必须一模一样"升级成
  "她的全部轮廓必须落在那个范围之内——从头顶呆毛尖到鞋底、从尾巴末端到头发外侧"，
  倍率从 1.51× 变成 **1.49×**。加实物参照（"头顶刚过人物膝盖"）也没用。
- **引导图里把她画小没有用**。从 21.3% 缩到 14.2%、10.6%，成品仍是 33.9%、31.2%
  （稳定在 31~34%，缩一半都不动）。
- **纯色剪影也不行**。把立绘换成品红剪影、要求"填满形状、边缘与剪影重合"，
  p01 出来 32.8%（贴立绘时 31.8%）。
- **这支 API 不支持 mask 局部重绘**。传 `mask` 返回 200，但静默忽略：
  两个深色矩形、mask 只框左边，结果两个都被换成了猫。
  `mask` / `mask_image` / `masking` 都不用再试。

**推论：不要用"多生成几张取最优"来救尺寸。** p01 上试了 7 次，
全部落在 31~45%，一次都没接近目标 21.3%——它不是随机误差，是下限。

*表情（三条）*

- **把 9 个表情全交给 VLM 选会塌缩**。第一版温柔占 5/10，改完变雀跃占 9/10。
  原因是它总能给最通用的选项找到理由——"她刚坐下、正处在兴头上"对每张照片都成立。
- **给动作加"表情映射"会抹平多样性**。10 张测试图都是同一个坐姿动作，
  映射把它们全导向同一张脸——而用户要的恰恰是"同一动作不同表情"。
- **表情描述里不能出现情绪词**。"她很害羞"出来还是那个笑；
  "两颊红到耳朵、眼睛往下看、嘴角抿着往上"才画得对。

*避让（一条）*

- **几何规则不能靠读代码验**。这一轮避让规则连错 5 处（方向判反、阈值太严、
  `sit_y` 取错边…），全部是**跑完整批 8 分钟才发现的**。
  成品"看起来还行"可能只是错的规则恰好没触发。
  → 必须在写规则的同时构造离线 case 断言（`step25_avoid_cases.py`，0.1 秒跑完）。

## 六、成本与性能台账

| 项 | 数值 |
|---|---|
| 图像生成（立绘路线） | 0 元 / 0 秒（立绘命中缓存） |
| 图像生成（引导生成） | 0.12 元 / 8~12 秒（规划 1 次 VLM + 生成 1 次） |
| 图像生成（场景内路线） | 0.12 元（Flash）/ 0.30 元（Pro），20~40 秒 |
| VLM 画像（含座面框 + 物品清单） | 5~7 秒（`objects` 加长后 max_tokens 提到 980）；**±30% 抖动，偶发整段 objects 缺失** |
| VLM 规划（`plan_scene`） | 4~6 秒（动作 + 表情两段候选清单，max_tokens 700） |
| VLM 物件检测 | **已取消**（并入画像）；仅在合并结果不可用时兜底问 |
| CPU 合成全链 | **0.55~0.76 秒**（原 1.8~3.5 秒） |
| 尺寸客观测量（`s3/measure.py`） | 约 0.1 秒（ROI 内 numpy diff） |
| 场景统计 + 表情收窄（`s3/moods.py`） | 约 0.02 秒（缩到 256 再算） |
| 碰撞避让（`s3/scene3d.py`） | 约 0.01 秒（纯几何，最多扫 120 个位置） |
| 避让回归用例（`step25`） | **0.1 秒 / 8 条**（离线，0 成本） |
| **单张总耗时** | 立绘路线 2.4~3.7s / 引导生成 16~22s |
| 立绘首次生成 | 一次性，每个姿态 1 张 |
| 已缓存立绘 | chibi 9 个姿态（含新版抱膝）/ mature 2 个 |

**打磨闭环的成本**（这一轮）：批量测试 10 张 × 3 轮 + 单项验证若干
≈ 60 次图像生成 ≈ **7 元**，累计约 3 小时。这类"规则对不对"的验证
如果每次都靠跑批量，成本和时间都不可接受——所以 `step25_avoid_cases.py`
那种离线用例的价值不只是快，是把验证从"每轮 1.2 元"降到"0 元"。
