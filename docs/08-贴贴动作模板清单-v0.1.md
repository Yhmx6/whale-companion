# 贴贴动作模板清单 v0.1

> 日期：2026-10-26
> 依据：13 个动作模板 × 真实调用 12 次（Flash，各 1 次）+ 前两轮 Pro/Flash 对照
> 代码：`prototype/s3/actions.py`（`ACTION_LIBRARY`）
> 分类图：`prototype/output/step4/action_matrix.jpg`

---

## 一、结论摘要

**贴贴可以做，但成败几乎完全取决于"手要做什么"。**

- 手只是**搭着、扶着、扒着、露出来** → 能做对（`shoulder` / `peek`）
- 手要**精确抓握**（抱住手臂、捏住衣角、拉住裤脚）→ 抓握感不足，变成"贴在旁边"
- 手要**贴脸、头靠头、牵手指** → 基本做不到

这条规律比"动作难不难"更准。原因很清楚：精细手部对位 + 双向遮挡，是这一代图像模型最弱的两件事叠在一起。

**当前默认只开放 2 个动作**（用户决定）：`shoulder`、`peek`。

## 二、可用模板清单（13 个）

### A 档 —— 现在就放开

| ID | 名称 | 需要的部位 | 适合景别 | 实测结论 |
|----|------|-----------|----------|----------|
| `shoulder` | 坐在肩膀上 | 肩膀、头 | 半身 / 全身 | **可用**。真的坐在肩上、两条短腿垂下、衣服上有接触暗部。Pro 版明显好于 Flash |
| `peek` | 扒着肩膀探头 | 肩膀 | 特写 / 半身 | **可用**。手只扒在肩线，遮挡关系最简单，是全部动作里最稳的一个 |

### B 档 —— 接近可用，下一轮用 Pro 复跑

| ID | 名称 | 需要的部位 | 适合景别 | 实测结论 |
|----|------|-----------|----------|----------|
| `shoulder_back` | 趴在肩后探身 | 肩膀、后背 | 半身 / 全身 | **接近可用**。在其右肩后方探身、手扒在肩附近，遮挡合理。本轮最意外的惊喜 |
| `hug_calf` | 抱住小腿 | 小腿、脚 | 全身 | **接近可用**。蹲在脚边贴着腿，位置对；但看不出手在环抱，更像靠着 |
| `on_head` | 坐在头顶 | 头顶 | 特写 / 半身 | **待优化**。偏到头发右侧，有悬浮感。需在提示词里锁死「正中央」 |
| `hug_thigh` | 抱大腿 | 大腿 | 全身 | **待优化**。身体贴在大腿侧面，姿态尚可，手部不清 |
| `hug_arm` | 抱住手臂 | 手臂 | 半身 / 全身 | **待优化**。比首轮好一些，但仍偏「贴在手臂旁」而非抱住 |

### C 档 —— 暂不开放

| ID | 名称 | 为什么不行 |
|----|------|-----------|
| `pull_hem` | 扯衣角 | 手没有真的捏住衣角，像站在卫衣前面 |
| `pull_trouser` | 扯裤脚 | 位置飘到腿外侧，手没有接触裤脚 |
| `pocket` | 从口袋里探出身 | 没有从口袋探出，实际贴在肩部。**口袋这类小区域模型定位不住** |
| `hand_hold` | 牵手 | 人物双手垂在身侧，没有可牵的手；手指对位是模型最弱项 |
| `lap` | 坐在腿上 | 底图是站姿，没有可坐的腿。**该动作必须配坐姿照片**，本轮属配对错误 |
| `cheek` | 贴脸 | 浮在脸旁，做不到头靠头。Pro/Flash 两轮都失败 |

## 三、难度分级的判据（可以直接套用到新动作）

写新动作前先问一句：**她的手要做什么？**

| 手的任务 | 难度 | 例子 |
|----------|------|------|
| 搭着 / 扶着 / 扒着 / 只是露出来 | 低 | 坐肩膀、扒肩探头、趴肩后 |
| 环抱一个圆柱体（腿、腰） | 中 | 抱小腿、抱大腿 |
| 捏住一小块布料 | 中高 | 扯衣角、扯裤脚 |
| 精确抓握、对位（牵手、捏手指） | 高 | 牵手 |
| 贴脸、头靠头 | 极高 | 贴脸 |

另外两条经验：
- **脸被挡住反而降低难度**（`hug_thigh` 脸埋进裤腿，比露出脸更容易成功）
- **需要小区域定位的动作基本做不成**（口袋、袖口、领口）

## 四、自动匹配怎么工作

`vlm_match_action()`：把候选动作清单 + 照片一起给视觉模型，让它挑一个并说明理由。

**闭式分类，不是开放描述。** 早期试过让它开放式回答"哪些身体部位可见"，结果不可靠——同一张图两次输出差异很大，甚至把半身照说成「小腿可见」。改成从清单里挑，准确率明显提升。

**速度靠一个参数**：`thinking: {"type": "disabled"}`。默认思考模式下这张图要 **39 秒 / 2000+ reasoning token**，关掉后 **1.5 秒 / 0 reasoning**。识图分类不需要长链推理。

实测两个例子：

| 照片 | 推荐 | 置信度 | 理由（原文节选） |
|------|------|--------|------------------|
| 沙发半身自拍 | `peek` | 0.9 | 人物双肩完整露出，肩后有足够空位；从肩后探头不会遮挡面部，无需精确抓握 |
| 公园全身照 | `shoulder` | 0.9 | 右肩清晰可见，头顶上方有空间；坐右肩不遮脸，仅需扶头发 |

匹配的判据按重要性排：①需要的部位在画面里可见且没被裁 ②不能挡住人物的脸 ③有足够空位 ④优先手部简单的动作。

## 五、提高单个动作成功率的写法

从实测与检索到的贴纸提示词经验里提炼，写进 `desc` 时按这几条：

1. **锁死方位词**：不说「坐在头顶」，说「盘腿**正坐在头顶的正中央**」（`on_head` 就是因为缺这个词才飘到侧面）
2. **说明遮挡关系**：明确「在她身体前方的手要挡住衣服，在后方的手要被身体挡住」
3. **要求接触阴影**：贴贴模式下要**要求模型画**接触暗部（与人单人模式相反——那时我们禁止画地面投影，因为影子该由程序算）
4. **人物完全不动**：把「脸、五官、表情、发型、服装、姿势都不许改」写在第一条，权重最高
5. **明示体积感**：「像一个可以带在身上的玩偶挂件」，比「很小」更有效
6. **禁止多余肢体**：单独一条「不要出现多余的手指、多余的肢体、断裂的肢体，不要让人物的手变形」

## 七、追记：试过"简化手的画法"，无效（2026-10-26 追加）

**问题**：既然失败都集中在手，那把手的画法简化掉行不行？

**做法**：加 206 字符的手部补丁，三种手法一起上——(a) 手被头发/衣服挡住只露圆轮廓、
(b) 环抱时手从物体后方绕过去看不见、(c) 抓握降级为整只手掌平贴按出褶皱。
拿三个偏弱的动作做 A/B（`pull_hem` / `hug_calf` / `hug_arm`，同底图同 seed 同引擎）。

**结果：无效，而且有害。**

| 项 | 结果 |
|----|------|
| 抓握问题 | **一点没解决**，手仍然不清晰 |
| 角色尺度 | **三张全部变大、位置漂移**（原本在脚边的飘到了膝盖以上） |
| 融合质量 | 更差，更像贴纸 |

**两个原因，都可复用：**

1. **否定式指令在这个模型上遵从度很低。**「不要画手指」和之前失败的「不要画白描边」是同一个模式。
   凡是「不要 X」这类指令，命中率都低。**要改就改动作设计，不要靠"不要"去堵。**
2. **加长提示词会稀释其他约束。** 206 个字符塞进去，「小巧」「挂件大小」这些约束的权重被摊薄，
   于是角色变大。这是提示词长度效应，不是手部那段写错了。

**所以正确答案是：能解决，但不在提示词层面，在动作设计层面。**

把判据从「手画得好不好」换成「**手的位置是否被结构遮挡**」：

| 判据 | 例子 | 结果 |
|------|------|------|
| 手天然处在遮挡位（头发、肩线、人体后方） | `shoulder` 手扶头发、`peek` 手扒肩线、`shoulder_back` 手在人身后 | 天然成功，不需要任何提示词 |
| 手的全部轮廓暴露在空处、还要表达抓握 | `pull_hem`、`pull_trouser`、`hand_hold` | 必然失败 |

**这条替换掉了原先「按手的任务分难度」的判据**，更好用——因为它不依赖提示词技巧，
在选动作的时候就能判断，而且和生产实现无关。

下一步该按这个判据重新筛动作：凡是"手必然暴露在空处"的动作，直接不放进产品，
而不是想办法把它救回来。

## 八、v2 重构：三维度 + 腿部约束（2026-10-26 晚）

### 8.1 重构原因

v1 只有"难度档位"，出了两个错：
1. 把所有贴贴当成"挂在人身上" → 站在地上的动作全部浮空（用户发现）
2. 光按"手的任务"排难度 → 救不回"手必须暴露在空处还要抓握"的动作

改成三个正交维度，每个都对应一个实现分支：

| 维度 | 取值 | 决定 |
|------|------|------|
| `support` | `person` / `ground` | 承重在哪 → 要不要程序化画地面阴影 |
| `hand_mode` | `hidden` / `self` / `occluded` / `flat` / `grip` | 手怎么呈现 → 成功率 |
| `anchor_region` | `legs` / `feet` / `shoulder` / `head` / `back` / `torso` / `beside` | 贴在哪 → 位置约束 |

**手部呈现方式的成功率排序（实测）：**

    hidden（完全看不见，如背在身后）
      > self（抱自己膝盖，接触结构明确、不涉及他人）
      > occluded（绕到腿后被挡住）
      > flat（手掌平贴）
      > grip（精确抓握，几乎必败）

核心洞察：**把"抓别人"换成"抓自己"或"手不存在"，问题就消失了。** 因为模型不需要理解两个物体之间的接触博弈，只需要画一个闭合的自身结构。

### 8.2 腿部位置约束（用户提出）

全身照时把角色约束在人物腿部附近。实现方式：

1. `vlm_locate(photo, "人物的双腿（从小腿到鞋）")` 让 VLM 输出归一化框
2. 把框写进提示词：`她必须出现在 Image 1 的 {x1} {y1} {x2} {y2} 这个区域内，紧贴着人物的小腿和脚`
3. 走的是已验证有效的坐标约束语法

实测定位精度：

| 底图 | 结果 |
|------|------|
| 公园全身照 | `[390, 575, 610, 985]`，合理 |
| 走廊全身照 | `[361, 525, 638, 988]`，合理 |
| 沙发半身照 | `[0, 917, 999, 999]` → **被校验拦掉**（腿不可见时 VLM 会返回贴着底边的整幅横条） |

所以加了退化框校验：宽度 > 850、高度 < 60、或 y1 > 900 一律判为不可用。
**半身照不会误用腿部约束，这点必须拦住，否则会把角色按到画面最底下。**

### 8.3 v2 实测结果（5 个新动作，Flash，1 分 25 秒）

| 动作 | hand_mode | 结果 |
|------|-----------|------|
| **leg_hug_knee** 坐在脚边抱膝盖 | `self` | **最好**。手抱自己膝盖，结构清楚无畸形，地面阴影正常 |
| **hem_peek** 扒着衣摆探头 | `flat` | **最自然**。扒在卫衣下摆探出上半身，衣摆是长边、定位准 |
| **leg_hands_behind** 站在腿边仰头 | `hidden` | **可用**。双手背在身后完全看不见；位置略偏脚外侧 |
| leg_lean 侧靠在小腿上 | `occluded` | 接近可用。位置对齐、脚落地有阴影，但与腿之间留缝，「靠」得不实 |
| foot_sit 坐在鞋面上 | `flat` | 未达成。结果站在鞋旁边；鞋面小且底图脚部侧向，坐不上去 |

**默认开放动作从 2 个变成 5 个**：`shoulder`、`peek`、`leg_hug_knee`、`hem_peek`、`leg_hands_behind`。

### 8.4 三条结论

1. **"抓自己"比"抓别人"简单一个数量级。** `hug_calf`（抱别人小腿，grip）偏弱，`leg_hug_knee`（抱自己膝盖，self）一次成功。差别不在动作难度，在于**接触关系的拓扑复杂度**：自己抱自己是一个闭合环，模型只需保证手和膝盖相连；抱别人需要同时满足手的位置、对方肢体的形状、遮挡方向三个约束。
2. **长边比小区域好定位。** `pocket`（口袋）失败，`hem_peek`（衣摆）成功——同样在躯干上，口袋是一个小矩形，衣摆是一条长边。**凡是需要在小面积上做精确放置的动作，先换成沿某条长边的动作。**
3. **坐标约束能定住"在哪"，定不住"怎么贴"。** 腿部约束生效了（角色确实都在腿边），但 `leg_lean` 还是靠着留缝、`foot_sit` 还是没坐上去。**位置可控 ≠ 接触可控**，这条和之前手部的结论一致。
